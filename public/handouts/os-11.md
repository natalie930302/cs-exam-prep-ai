# 虛擬化與安全

一台實體電腦的 CPU 和記憶體常常用不完，虛擬化 (virtualization) 把它切成好幾台「虛擬電腦」同時跑，雲端資料中心和個人電腦上的虛擬機都靠它。負責切資源、管理虛擬機的軟體叫 hypervisor。考試最常考的是 **Type 1（bare-metal）和 Type 2（hosted）hypervisor 的差別**，以及各自的優缺點從哪裡來。本章最後再整理作業系統保護與安全的基本觀念。

## 學完這章要會
- 說出 virtual machine、hypervisor（VMM）、host、guest 各是什麼
- 解釋 hypervisor 怎麼讓一台電腦變成多台：切 memory 和 CPU 時間
- 分辨 Type 1 與 Type 2：hypervisor 放在哪一層、host 要不要先裝 OS、各舉例子
- 列出 hypervisor 的優缺點，並看出哪些缺點其實只屬於 Type 2
- 知道不需要 hypervisor 的替代方案（container）
- 分清 protection 與 security，說出常見的保護機制

## Virtual machine 與 hypervisor

**Virtual machine（VM，虛擬機）**：用軟體模擬出來的一台電腦，裡面可以裝自己的作業系統，跑自己的應用程式。

**Hypervisor**：專門用來**建立和管理 virtual machine** 的軟體。它夾在中間：下面是實體硬體，上面才是一台台 VM。

> **重點** hypervisor 的另一個名字是 **virtual machine monitor（VMM）**。考卷上兩個名字都會出現，意思一樣。

有了 hypervisor，一台實體電腦就能同時跑好幾台虛擬電腦：

- 實體的那台叫 **host**（主機、主人）
- 上面的虛擬電腦叫 **guest**（客人）
- 每台 guest 都有自己的作業系統和應用程式（下圖畫三台只是示意，實際上可以更多）

```
 ┌─────────┐ ┌─────────┐ ┌─────────┐
 │ App     │ │ App     │ │ App     │
 │ Guest OS│ │ Guest OS│ │ Guest OS│   ← guest（VM）
 └─────────┘ └─────────┘ └─────────┘
 ┌─────────────────────────────────┐
 │        Hypervisor (VMM)         │   ← 切資源、管理 VM
 └─────────────────────────────────┘
 ┌─────────────────────────────────┐
 │     實體硬體 CPU / memory / ...    │   ← host
 └─────────────────────────────────┘
```

### 怎麼做到的：切分資源

Hypervisor 把實體電腦的 **memory** 和 **processing（CPU 時間）** 切成好幾份，分給各台 VM。切開之後，每一份對裡面的作業系統來說，都像一台分開、獨立的電腦，它根本不知道旁邊還有別人。讓這個假象成立，就是 hypervisor 的工作。

### 為什麼需要 hypervisor

1. **充分利用硬體**：一台電腦的能力常常用不完，切給好幾台 VM 就不會閒置。
2. **管理有彈性**：要新增、移除、調整一台「電腦」都只是軟體操作，IT 管理方便很多。
3. **可以搬家（migrate）**：VM 不綁定底下的實體硬體，所以能很輕鬆地從一台 server 搬到另一台。

> **例題** 某台 server 要停機維修，上面跑著好幾台 VM。怎麼讓服務不要停太久？
> 答：先把這台 server 上的 VM migrate 到隔壁那台 server，再維修原本那台。因為 VM 不綁定特定實體硬體，搬過去就能繼續跑。

## Type 1 與 Type 2 hypervisor

Hypervisor 分兩種，Type 1 和 Type 2。不管哪一種，「切分資源給 VM」的原理都一樣；VM 也可以建在各式各樣的 hypervisor 上。兩型的差別只在 **hypervisor 自己放在哪一層**。

```
      Type 1（bare-metal）            Type 2（hosted）
 ┌───────┐┌───────┐┌───────┐    ┌───────┐┌───────┐┌───────┐
 │ Guest ││ Guest ││ Guest │    │ Guest ││ Guest ││ Guest │
 └───────┘└───────┘└───────┘    └───────┘└───────┘└───────┘
 ┌─────────────────────────┐    ┌─────────────────────────┐
 │       Hypervisor        │    │       Hypervisor        │
 └─────────────────────────┘    └─────────────────────────┘
 ┌─────────────────────────┐    ┌─────────────────────────┐
 │        Hardware         │    │  Host OS（Windows 等）    │
 └─────────────────────────┘    └─────────────────────────┘
                                ┌─────────────────────────┐
                                │        Hardware         │
                                └─────────────────────────┘
```

### Type 1：bare-metal hypervisor

- **直接跑在硬體上**，中間沒有別的作業系統：最下面 hardware，上面 hypervisor，再上面就是 guest。
- bare metal 是「裸機」的意思：直接裝在還沒有作業系統的機器上。
- 在實體 server 上，**Type 1 hypervisor 自己就扮演 host 的作業系統**，管硬體、分資源都由它來做。
- 少了一層作業系統，通常**效能比較好**，能被攻擊的地方也**比較少**。
- 例子：資料中心的 server 常用，像 VMware ESXi、Xen。

### Type 2：hosted hypervisor

- hosted 是「寄居」的意思：**跑在一個已經裝好的作業系統（host OS）上面**，像 Windows、macOS，就跟一般應用程式一樣；guest 再跑在它上面。
- 所以用 Type 2 之前，**host 一定要先裝好作業系統**。
- 好處：在自己的電腦上就能用，很方便。
- 代價：多了一層 host OS，**效能和安全都受它影響**。
- 例子：在筆電上用 VirtualBox 或 VMware Workstation 開虛擬機。

| | Type 1（bare-metal） | Type 2（hosted） |
|---|---|---|
| 跑在哪裡 | 直接在硬體上 | 在 host OS 上，像一般應用程式 |
| host 要先裝 OS 嗎 | 不用，hypervisor 本身就是 host 的 OS | 要 |
| 效能 | 通常較好（少一層） | 受 host OS 影響 |
| 安全 | 攻擊面較小 | host OS 有漏洞就跟著曝險 |
| 常見場合 | 資料中心 server | 個人電腦、筆電 |
| 例子 | VMware ESXi、Xen | VirtualBox、VMware Workstation |

> **重點** 一句話分辨：Type 1 直接在硬體上，hypervisor 就是 host 的 OS；Type 2 寄居在 host OS 上。

## Hypervisor 的優點與缺點

### 優點

1. **Quickness（快）**：需要一台新電腦時，開一台 VM 比準備一台實體的 bare-metal server 快很多，遇到複雜的工作能很快分到需要的資源。
2. **Efficiency（效率）**：一台 server 同時跑好幾台 VM，硬體資源不會閒在那裡。

### 常被列出的缺點

1. **需要外部管理介面**：要控制 hypervisor，需要另外一套系統或另一台機器。
2. **比較不安全**：hypervisor 依賴 host OS 時，host OS 一有漏洞，上面的 hypervisor 和 VM 都跟著曝險。
3. **比較不可靠**：host OS 一當機，跑在上面的 hypervisor 和所有 VM 全部一起倒。
4. **資源受限**：hypervisor 得跟 host OS 一起分 CPU 和 storage，永遠拿不到硬體資源的完全控制權。
5. 「hypervisor 不是設計來在個人桌機上跑 VM 的」。

> **陷阱** 缺點 2、3、4 都寫著「依賴 host OS」或「跟 host OS 分資源」，這其實只發生在 **Type 2**；Type 1 底下根本沒有 host OS。考題問「Type 1 的缺點」時不要把這幾項照抄過去。

> **陷阱** 缺點 5 要修正：Type 1 確實多半用在 server，但 Type 2（像 VirtualBox）正是給個人電腦用的。不能說所有 hypervisor 都不適合桌機。

### 替代方案：不需要 hypervisor 的虛擬化

也有不需要 hypervisor 的虛擬化工具可以當替代方案，例如 **container**：好幾個程式共用同一個作業系統核心（kernel），不用每台都裝一整套 OS。

> **觀念** VM 是「每台 guest 一整套 OS」，由 hypervisor 切硬體資源；container 是「多個程式共用 host 的 kernel」，比較輕量。

## 作業系統的保護與安全

這一節整理 OS 保護與安全的基本觀念（檔案權限的細節見檔案系統那章）。

### Protection 與 security

- **Protection（保護）**：系統**內部**的機制，控制 process 或 user 能存取哪些資源（檔案、記憶體、CPU、裝置），以及能做哪些操作。
- **Security（安全）**：防範系統**外部**的威脅，例如未經授權的存取、惡意破壞；前提是先有 protection 機制，再加上認證等手段。

> **觀念** 檔案系統那章把 protection 再分成兩類：防止 **damage**（資料毀損，例如用 RAID 做備援）與 **security**（不讓別人亂動，例如 password、ACL、encryption）。

### 常見的保護機制

- **Dual mode（user mode／kernel mode）**：特權指令只能在 kernel mode 執行，user program 要透過 system call 請 OS 代勞，這是硬體層的保護基礎。
- **記憶體保護**：每個 process 只能存取自己的位址空間（base/limit register、paging 的 page table 與 valid bit），越界就 trap 給 OS。
- **CPU 保護**：timer 定時中斷，防止某個 process 霸佔 CPU 不還。
- **存取控制**：用 access-control list（ACL）記錄「誰能對這個物件做什麼」；UNIX 把它簡化成 owner／group／others 各 rwx 三個 bit。
- **最小權限原則（principle of least privilege）**：每個 user、process 只給完成工作所需的最少權限，出事時損害最小。
- **Authentication（認證）**：確認使用者身分，最常見的是 password。
- **Encryption（加密）**：資料就算被拿走也讀不懂。

> **觀念** 虛擬化本身也是一種隔離：每台 guest 都以為自己獨佔一台電腦，一台 VM 出問題不會直接影響其他 VM；但 Type 2 的 host OS 若被攻破，上面所有 VM 都會曝險。

## 重點整理
- VM：軟體模擬的電腦，可以裝自己的 OS
- hypervisor = virtual machine monitor（VMM）：建立與管理 VM 的軟體
- host = 實體電腦；guest = 上面的虛擬電腦，各有自己的 OS 和應用程式
- 原理：把 memory 和 CPU 時間切給各 VM，每台都以為自己是獨立電腦
- 好處：充分利用硬體、管理有彈性、VM 可以 migrate 到別台 server
- Type 1 = bare-metal：直接跑在硬體上，hypervisor 自己就是 host 的 OS；效能好、較安全；ESXi、Xen
- Type 2 = hosted：跑在已裝好的 host OS 上，host 要先裝 OS；方便但效能、安全受 host OS 影響；VirtualBox、VMware Workstation
- 優點：quickness、efficiency
- 缺點：需要外部管理介面；不安全、不可靠、資源受限這三項都是「依賴 host OS」的 Type 2 問題
- 「hypervisor 不適合桌機」只對 Type 1 成立，Type 2 正是給桌機用的
- 替代方案：container，多個程式共用同一個 OS kernel
- protection 管內部存取控制，security 防外部威脅；機制：dual mode、記憶體保護、timer、ACL／rwx、最小權限、認證、加密
