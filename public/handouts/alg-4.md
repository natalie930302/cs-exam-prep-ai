# 動態規劃（進階）

這一章用同一套 DP 五步驟，解幾個考試最愛的經典題：矩陣連乘（matrix chain multiplication）、最佳二元搜尋樹（optimal BST）、可靠度設計（reliability design）、編輯距離（edit distance）與背包（knapsack）。接著學一個更高層的技巧：當直覺的子問題資訊不夠時，讓子問題「多記一點」，一路解到吉他指法、Tetris、Super Mario Bros. 和跳舞機 DDR。考試最常考的是手算矩陣連乘與 optimal BST 的表格並還原答案、寫出遞迴式、說出時間複雜度，以及 pseudo-polynomial 的意義。

## 學完這章要會

- 背出 DP 五步驟，以及「執行時間 = 子問題個數 × 每個子問題的時間」。
- 輸入是字串／序列時，會在 suffix、prefix、substring 三種子問題之間選擇，並知道各有幾個。
- 算兩個矩陣相乘的乘法次數；寫出矩陣連乘的遞迴式 m(i,j) = min{ m(i,k) + m(k+1,j) + d(i−1)·d(k)·d(j) }。
- 手填矩陣連乘的 m 表與 s 表（維度 5,4,6,2,7 → 158；維度 3,2,4,2,5 → 58），用 s 表還原括號，追蹤 C 程式。
- 說出括法數是 Catalan 數，矩陣連乘的時間是 Θ(n³)，以及為什麼它「不是」DAG 最短路徑。
- 算 BST 的成功／失敗搜尋成本；寫出 optimal BST 的 c(i,j) = min{ c(i,k−1) + c(k,j) } + w(i,j)，手填 w、c、r 表並建出樹。
- 用集合法（有序對）加 dominance rule 解 reliability design，並回溯出每種裝置買幾份。
- 寫出 edit distance 的 DP(i,j) 三種選項、拓撲順序、Θ(|x|·|y|)，並把 LCS 化成 edit distance。
- 寫出 knapsack 的 DP(i,X)，說明為什麼 n·S 是 pseudo-polynomial 而不是 polynomial。
- 會用「第二種猜」：替子問題加參數（指法的手指、Tetris 的 skyline、Mario 的 configuration、DDR 的腳位），並算出各自的時間。

## DP 五步驟

每一題都照同一套食譜走：

1. **定義子問題（subproblem）**：小一號、形狀一樣的題目，而且要數一數總共有幾個。
2. **猜（guess）**：解的某一部分不知道，就把所有可能都試一遍；但選擇的個數必須是多項式個。
3. **寫遞迴式（recurrence）**：把目前的子問題用更小、已經會解的子問題表示。遞迴式通常長成「一堆選項取 min 或 max」，每個選項對應一種猜法。順便算每個子問題花多少時間，遞迴呼叫的部分當作免費、不算進去。
4. **變成演算法**：直接遞迴加 memoize（top-down），或由小到大填表（bottom-up），兩種做的計算幾乎一樣。遞迴版要確認遞迴式沒有環（acyclic），不會繞回來依賴自己，否則無限遞迴；bottom-up 版要排出拓撲順序（topological order）。其實這兩件事是同一件：排得出拓撲順序，就證明了沒有環。
5. **解原問題**：原問題可能剛好是某一個子問題，也可能要拿幾個子問題來比、取最好的。

> **重點** 執行時間 = 子問題個數 × 每個子問題的時間（遞迴呼叫不算）。這個公式在每一題都會用到，一定要背。

### 字串的子問題：suffix、prefix、substring

五步驟裡最難的是第一步，大部分的巧思都在「子問題怎麼定」。子問題選對了，要猜什麼通常很明顯，遞迴式幾乎自己跑出來。

輸入是一個字串或序列 x 時（例如排版 text justification 的輸入是一串單字、21 點 blackjack 是一串牌），有三招通用的子問題：

| 子問題 | 寫法 | 個數 | 什麼時候用 |
|---|---|---|---|
| 後綴 suffix | x[i:]，從第 i 個到最後 | 約 n+1 個 | 每次從前面拿掉一點，剩下的永遠是 suffix |
| 前綴 prefix | x[:i]，從開頭到第 i 個之前 | 約 n+1 個 | 每次從後面拿掉一點，剩下的永遠是 prefix |
| 子字串 substring | x[i:j]，從 i 到 j 的連續一段 | 約 n² 個 | 前兩種都不夠用時 |

suffix 好用的原因：每次從前面拿掉一點，剩下的還是 suffix，子問題不會跑出這個「家族」。所以能用 suffix、prefix 就先用（比較少），不行再退到 substring（還是多項式）。這三招很簡單，卻能應付大部分的 DP 題。

> **陷阱** substring 一定是**連續**的一段，不是可以跳著挑的 subsequence（子序列）。substring 只有約 n² 個，subsequence 卻有 2ⁿ 個。

> **重點** 經驗法則：如果一個問題同時需要 prefix 和 suffix，通常就該改用 substring。矩陣連乘就是這樣。

## 矩陣連乘 Matrix Chain Multiplication

### 兩個矩陣相乘的成本

A 是 5×4、B 是 4×3。

- **能不能乘**：第一個的 column 數要等於第二個的 row 數。A 有 4 行、B 有 4 列，可以乘。反過來 B×A：B 的 3 行對 A 的 5 列，3 ≠ 5，不能乘。A×B 能乘，不代表 B×A 能乘。
- **結果多大**：取兩端的維度，列數跟 A、行數跟 B，所以 C 是 5×3，有 15 個元素。
- **要做幾次乘法**：C 的每個元素都是 A 的一整列和 B 的一整行對應相乘再相加，一列 4 個數，所以每個元素 4 次乘法。總共 5·3·4 = 60 次，其實就是三個維度 5、4、3 乘起來。

再一個例子：2×3 乘 3×2，結果 2×2 共 4 個元素，每個 3 次乘法，2·3·2 = 12 次。

> **重點** p×q 的矩陣乘 q×r 的矩陣，成本 = p·q·r 次乘法，結果是 p×r。後面比哪種順序省，比的就是這個數字。

兩個矩陣寫下來有 4 個維度，但中間兩個一定相同，所以只有 3 個不同的數。這就是等一下維度編號 d₀、d₁、d₂…的由來：**相鄰矩陣共用的維度只記一次**。

### 三個矩陣：括法不同，成本不同

A₁ 是 2×3、A₂ 是 3×4、A₃ 是 4×2。相鄰的 3 對 3、4 對 4 都對得上，可以一路乘。把維度取名：d₀ = 2、d₁ = 3、d₂ = 4、d₃ = 2，第 i 個矩陣是 d(i−1)×d(i)。

三個矩陣不能一次一起乘，一次只能乘兩個，所以有兩種順序。因為矩陣乘法有結合律（associative），兩種答案完全一樣；但我們不在乎裡面的數字，只在乎要花多少力氣，也就是乘法次數。

| 括法 | 第一次乘 | 第二次乘 | 合計 |
|---|---|---|---|
| (A₁A₂)A₃ | A₁A₂：2·3·4 = 24，結果 2×4；A₃ 單獨 0 次 | 2×4 乘 4×2：2·4·2 = 16 | 24 + 0 + 16 = 40 |
| A₁(A₂A₃) | A₂A₃：3·4·2 = 24，結果 3×2；A₁ 單獨 0 次 | 2×3 乘 3×2：2·3·2 = 12 | 0 + 24 + 12 = 36 |

答案一樣，成本卻不同：40 對 36，A₁(A₂A₃) 比較好。三個矩陣只差 4 次，好像沒什麼；但矩陣一多，例如 A₁ 到 A₁₀，傻傻從左乘到右可能貴得要命。所以要**先算好怎麼乘最省，再真的動手乘**。

> **重點** Matrix chain multiplication：給一串可以相乘的矩陣，決定括號（乘的順序），讓總乘法次數最少。問題不是把答案乘出來，而是決定「先乘哪一對」。

### 另一種說法：parenthesization（加括號問題）

更一般的說法：給一個有結合律的運算式，決定計算順序。例如 n 個矩陣 A₀·A₁·…·Aₙ₋₁ 相乘（這種寫法從 0 開始編號）。

- 矩陣乘法**沒有交換律**，A·B 不一定等於 B·A，所以矩陣的排列順序不能動。
- 能選的只有括號放在哪；因為有結合律，怎麼括答案都一樣，但成本可以差很多。

> **例題** 直行向量（n×1）乘橫列向量（1×n）再乘直行向量（n×1），哪種括法好？
> - 先乘前兩個：每一列配每一行，得到 n×n 的方陣，光是方陣就有 n² 個數要算，至少 Θ(n²)。
> - 先乘後兩個：橫列乘直行，結果只是一個數（1×1）；再拿這個數乘直行向量，Θ(n) 就好。
> - 一個 n²、一個 n，括號放對差了一整個量級。

不管用哪種矩陣乘法演算法，只要「x×y 和 y×z 相乘的成本能從維度算出來」，同一個 DP 都能處理。標準算法的成本就是 x·y·z。

### 有幾種括法：Catalan 數

主要例題：四個矩陣 A₁ 5×4、A₂ 4×6、A₃ 6×2、A₄ 2×7。例如 ((A₁A₂)A₃)A₄ 是從左一路乘到右；(A₁A₂)(A₃A₄) 是兩對各自先乘、最後合起來；還有 A₁(A₂(A₃A₄)) 等等。

括號可以畫成一棵二元樹：樹葉是矩陣，每個乘號節點就是一次兩矩陣相乘。四個矩陣要乘 3 次，所以樹上剛好 3 個乘號節點，不同的樹形就是不同的括法。n 個節點的二元樹有幾種？Catalan 數：

```
C(n) = (2n 取 n) / (n+1)
n = 3：(6 取 3) / 4 = 20 / 4 = 5   → 4 個矩陣有 5 種括法
n = 4：(8 取 4) / 5 = 70 / 5 = 14  → 5 個矩陣有 14 種括法
```

> **陷阱** 代進 Catalan 數的 n 是**乘號的個數**，也就是「矩陣數 − 1」，不是矩陣數。另外「5 個矩陣有 14 種」說的是 14 種括法，不是 14 次乘法。

括法數大約是 4ⁿ 級，指數成長，暴力把每種都算一遍完全不行。DP 的精神也是試過所有可能，但它**有系統地試**，不漏也不重複。做法是 tabulation（填表）：兩張表，m 存最小成本，s 存在哪裡切開。

### 推出公式

回到三個矩陣的兩個算式，我們要的是 C(1,3)：A₁ 乘到 A₃ 的最小成本。

- 第一式 24 + 0 + 16：24 是 A₁A₂ 的成本，寫成 C(1,2)；0 是 A₃ 自己，C(3,3) = 0；16 是最後把 2×4 和 4×2 相乘，用到 d₀·d₂·d₃。
- 第二式 0 + 24 + 12：0 是 C(1,1)，24 是 C(2,3)，12 是 d₀·d₁·d₃。

觀察：兩式頭尾都是 1 和 3，叫它們 i 和 j；d₀ 就是 d(i−1)、d₃ 就是 d(j)。中間切開的位置叫 k：左邊 C(i,k)、右邊 C(k+1,j)；第一式 k = 2、第二式 k = 1，中間那個維度跟著 k 走，就是 d(k)。左段結果是 d(i−1)×d(k)、右段結果是 d(k)×d(j)，相乘成本 d(i−1)·d(k)·d(j)。

```
m(i,i) = 0
m(i,j) = min { m(i,k) + m(k+1,j) + d(i−1)·d(k)·d(j) }，i ≤ k < j
```

白話：左邊的成本，加右邊的成本，再加把兩邊結果乘起來的成本；換不同的 k 就是試所有切法，挑最小的。

> **重點** n 個矩陣有 n+1 個維度 d₀…dₙ，第 i 個矩陣是 d(i−1)×d(i)。k 從 i 試到 j−1。

### 從「猜」的角度看同一個公式

面對整串矩陣，要猜最佳解的哪一部分？整個括法有指數多種，不能整個猜，只能猜一小塊而且要有進展：**猜最後一次乘法**，也就是最外層那個乘號。最後一次一定是「左半段的結果 × 右半段的結果」，兩半各自先乘好；切點 k 不知道，就全部試一遍取最好的。

左半像 prefix、右半像 suffix，那子問題用 prefix 加 suffix 就夠了嗎？不夠：接著遞迴解左半，又要在某個 k′ 再切一刀，切出來的 A_k′…Aₖ₋₁ 是中間一段，既不是 prefix 也不是 suffix，而是 substring。所以子問題是 **A[i:j] = Aᵢ…Aⱼ₋₁ 這一段的最佳乘法**（從 0 編號、j 不含）。從 substring 再猜一次，切出來的 A[i:k] 和 A[k:j] 還是 substring，子問題家族是封閉的。

0 編號的遞迴式：

```
DP(i, j) = min over k in range(i+1, j) of
           DP(i, k) + DP(k, j) + cost(A[i:k] 的結果 × A[k:j] 的結果)
base case：DP(i, i+1) = 0      （只有一個矩陣，不用乘）
原問題：DP(0, n)
```

最外層那次乘法的成本只看兩個結果矩陣的維度：左段第一個矩陣的列數、右段最後一個矩陣的行數，常數時間算得出來。k 的選擇不超過 n 種。

> **觀念** 這個遞迴式等於「神奇地」考慮了所有指數多種括法，卻只花多項式時間。「猜」的威力要真懂，就多看例子、自己寫程式。

### 為什麼不直接遞迴：先算小的

直接套公式求四個矩陣的 C(1,4)，k 可以是 1、2、3：

- k = 1：C(1,1) + C(2,4) + d₀·d₁·d₄，代表 A₁ 單獨、A₂A₃A₄ 一組。
- k = 2：C(1,2) + C(3,4) + d₀·d₂·d₄，代表 (A₁A₂)(A₃A₄)。
- k = 3：C(1,3) + C(4,4) + d₀·d₃·d₄，代表 A₁A₂A₃ 一組、A₄ 單獨。

C(1,1)、C(4,4) 是單一矩陣，已知是 0；但 C(2,4) 不知道，又要套公式展開（k = 2、3），展開出來的又要再展開，一路下去太長了。而且 C(3,4) 在展開裡出現好幾次。

所以反過來：**先把小的算好、存起來，再算大的**。大小看 j−i：差 1 的只有 1 種切法、差 2 的比 2 項、C(1,4) 差 3 要比 3 項。順序是 j−i = 0、1、2、3，由小到大填表。算一次存起來、要用直接拿，DP 省的就是這個。

> **重點** 填表順序：依 substring 的長度（j−i）由短到長。算 m(i,j) 之前，比它短的 m(i,k)、m(k+1,j) 都已經在表裡。

### 子問題 DAG：這個 DP 不是最短路徑

把子問題畫成 DAG：最上面是整串 (0, n)，最下面是最短的 substring，邊都往上指，所以短的先算。回顧拓撲順序：suffix 幾乎都由右往左算，prefix 由左往右算，substring 則依長度由短到長（suffix 其實也一樣：最右邊的 suffix 是空的，一路變長）。

> **陷阱** 常見誤會：「DP 一定是 DAG 上的最短路徑」。矩陣連乘的每個子問題要把**兩個**子問題的值相加，再加上這一刀的成本，不是沿著一條路徑走，所以它不是最短路徑。大多數 DP 可以看成 DAG 最短路徑，但不是全部。

> **觀念** 真的乘矩陣也要時間，規劃不會白花嗎？矩陣個數通常遠小於矩陣大小，DP 規劃的成本比真正做乘法小得多。

### 例題一：維度 5, 4, 6, 2, 7

> **例題** 四個矩陣 A₁ 5×4、A₂ 4×6、A₃ 6×2、A₄ 2×7，即 d₀…d₄ = 5, 4, 6, 2, 7。求最少乘法次數與括法。

**j−i = 0（對角線）**：只有一個矩陣，沒跟誰乘，m(1,1) = m(2,2) = m(3,3) = m(4,4) = 0。用公式看也一樣：m(1,1) 要 1 ≤ k < 1，找不到 k，沒東西可加，就是 0。

**j−i = 1（相鄰兩個）**：只有一種乘法，三個維度相乘。

| 格子 | 計算 | 值 | s |
|---|---|---|---|
| m(1,2) | 5·4·6 | 120 | 1 |
| m(2,3) | 4·6·2 | 48 | 2 |
| m(3,4) | 6·2·7 | 84 | 3 |

s(1,2) = 1 表示在 A₁ 後面切。為什麼要記 s？算一格時會比好幾個 k，一定要記住是哪個 k 給出最小值，等一下才能找出括號。

**j−i = 2（三個一組）**：

| 格子 | k | 計算 | 值 |
|---|---|---|---|
| m(1,3) | 1：A₁(A₂A₃) | m(1,1) + m(2,3) + 5·4·2 = 0 + 48 + 40 | **88** |
| m(1,3) | 2：(A₁A₂)A₃ | m(1,2) + m(3,3) + 5·6·2 = 120 + 0 + 60 | 180 |
| m(2,4) | 2：A₂(A₃A₄) | m(2,2) + m(3,4) + 4·6·7 = 0 + 84 + 168 | 252 |
| m(2,4) | 3：(A₂A₃)A₄ | m(2,3) + m(4,4) + 4·2·7 = 48 + 0 + 56 | **104** |

m(1,3) = 88、s(1,3) = 1（A₁ 單獨、A₂A₃ 一組）；m(2,4) = 104、s(2,4) = 3（切在 A₃ 後面）。這就是在試所有可能，但很輕鬆：要用的 m(2,3)、m(3,4) 表裡都有，直接拿。

**j−i = 3（四個全部）**：左邊放 1 個、2 個或 3 個矩陣，切法就這三種。

| k | 意義 | 計算 | 值 |
|---|---|---|---|
| 1 | A₁(A₂A₃A₄) | m(1,1) + m(2,4) + 5·4·7 = 0 + 104 + 140 | 244 |
| 2 | (A₁A₂)(A₃A₄) | m(1,2) + m(3,4) + 5·6·7 = 120 + 84 + 210 | 414 |
| 3 | (A₁A₂A₃)A₄ | m(1,3) + m(4,4) + 5·2·7 = 88 + 0 + 70 | **158** |

m(1,4) = 158，s(1,4) = 3。四個矩陣最少 158 次乘法。

> **陷阱** 這裡的候選值是 244 和 414，不是 200、400，也不是 204；手算時常在這一步算錯，但最小值 158 不受影響。

完成的兩張表（i 是列、j 是行，只用上半部）：

```
m 表                          s 表
     j=1  j=2  j=3  j=4            j=2  j=3  j=4
i=1    0  120   88  158      i=1     1    1    3
i=2         0   48  104      i=2          2    3
i=3              0   84      i=3               3
i=4                   0
```

也可以把上半張轉成三角形來畫，對角線的 0 排在最底下，從一邊看是 row i、從另一邊看是 column j：

```
              158
           88     104
       120     48     84
     0      0      0      0
```

### 用 s 表找出括號

158 有了，但到底怎麼乘？答案在 s 表，每格記著最佳切點：

1. s(1,4) = 3：在 A₃ 後面切開，左邊 A₁…A₃、右邊 A₄ 自己 → (A₁A₂A₃)(A₄)。
2. 左邊看 s(1,3) = 1：A₁ 單獨、A₂…A₃ 一組 → (A₁(A₂A₃))。
3. A₂…A₃ 只剩兩個，s(2,3) = 2，直接乘。

```
          ×            ← s(1,4)=3
        /   \
       ×     A4        ← s(1,3)=1
      / \
    A1   ×             ← s(2,3)=2
        / \
      A2   A3
```

樹葉從左到右就是 A₁、A₂、A₃、A₄。順序：先乘 A₂A₃，結果和 A₁ 相乘，最後乘 A₄，也就是 **((A₁(A₂A₃))A₄)**。驗算：48 + 40 + 70 = 158。

程式要印出括號？對這棵樹做 in-order 走訪：進去時印左括號、出來時印右括號。

### 例題二：維度 3, 2, 4, 2, 5

> **例題** d₀…d₄ = 3, 2, 4, 2, 5（A₁ 3×2、A₂ 2×4、A₃ 4×2、A₄ 2×5）。這次成本表叫 C、切點表叫 K（表的名字不重要，m/C、s/K 都有人用）。

| 格子 | k 的候選 | 值 | K |
|---|---|---|---|
| C(1,2) | k=1：0 + 0 + 3·2·4 = 24 | 24 | 1 |
| C(2,3) | k=2：0 + 0 + 2·4·2 = 16 | 16 | 2 |
| C(3,4) | k=3：0 + 0 + 4·2·5 = 40 | 40 | 3 |
| C(1,3) | k=1：0 + 16 + 3·2·2 = 28；k=2：24 + 0 + 3·4·2 = 48 | 28 | 1 |
| C(2,4) | k=2：0 + 40 + 2·4·5 = 80；k=3：16 + 0 + 2·2·5 = 36 | 36 | 3 |
| C(1,4) | k=1：0 + 36 + 3·2·5 = 66；k=2：24 + 40 + 3·4·5 = 124；k=3：28 + 0 + 3·2·5 = 58 | 58 | 3 |

C(1,4) = 58、K(1,4) = 3、K(1,3) = 1，括法剛好也是 (A₁(A₂A₃))A₄。最少 58 次，別的括法要 124 次，多了一倍以上，所以先算好再動手絕對值得。

> **陷阱** k = 1 那項是 0 + 36 + 30 = 66（不是 86）。

### 程式

維度存在陣列 p：共用的只存一次，5, 4, 6, 2, 7 就是 p[0]…p[4]，剛好對上 d₀…d₄。再開兩個二維陣列，m 存最小成本、s 存最佳切點。

- 為什麼開 5×5？C 陣列從 0 開始，要有索引 4，第 4 個矩陣才用得到第 4 列；開 4 只到 3。所以第 0 列、第 0 行用不到。
- 陣列一開始全設成 0，對角線 m[i][i] = 0 就自動完成。
- 要填的是三條對角線：差 1 的三格 (1,2)(2,3)(3,4)、差 2 的兩格 (1,3)(2,4)、差 3 的一格 (1,4)。
- 最外層迴圈 d 就是 j−i，一次處理一條對角線：n = 5（p 的長度），d 從 1 到 n−2 = 3。
- j = i + d（同一條對角線上 j−i 固定是 d）。
- 中間迴圈 i 是列：d = 1 有 3 列、d = 2 有 2 列、d = 3 只有 1 列，i 從 1 到 n−d−1，越上面的對角線越短。
- 最內層迴圈試每個 k（i 到 j−1），套公式找最小值；q 比目前的最小值小，就同時更新 m[i][j] 和 s[i][j] = k。

```c
#include <stdio.h>

int n = 5;                       // p 的長度 = 矩陣數 + 1
int p[] = {5, 4, 6, 2, 7};
int m[5][5] = {0};
int s[5][5] = {0};

void printParen(int i, int j) {  // in-order 走訪 s 表畫出的樹
    if (i == j) { printf("A%d", i); return; }
    printf("(");
    printParen(i, s[i][j]);
    printParen(s[i][j] + 1, j);
    printf(")");
}

int main(void) {
    int i, j, k, d, q, min;
    for (d = 1; d < n - 1; d++) {            // d = j - i：第幾條對角線
        for (i = 1; i < n - d; i++) {        // 這條對角線上的每一列
            j = i + d;
            min = 32767;
            for (k = i; k <= j - 1; k++) {   // 試每個切點
                q = m[i][k] + m[k + 1][j] + p[i - 1] * p[k] * p[j];
                if (q < min) {
                    min = q;
                    s[i][j] = k;             // 記下最佳切點
                }
            }
            m[i][j] = min;
        }
    }
    printf("%d\n", m[1][n - 1]);             // 158
    printParen(1, n - 1);                    // ((A1(A2A3))A4)
    return 0;
}
```

> **例題** 追蹤 d = 2、i = 1：j = 3，k 跑 1、2。
> - k = 1：m[1][1] + m[2][3] + p[0]·p[1]·p[3] = 0 + 48 + 5·4·2 = 88，比 min 小 → min = 88、s[1][3] = 1。
> - k = 2：m[1][2] + m[3][3] + p[0]·p[2]·p[3] = 120 + 0 + 5·6·2 = 180，不比 88 小，不更新。
> - 迴圈結束 m[1][3] = 88。兩個 k 剛好就是三個矩陣的兩種括法。
>
> 接著 i = 2、j = 4：k = 2 得 252、k = 3 得 104 → m[2][4] = 104、s[2][4] = 3。d = 3 時 i = 1、j = 4：244、414、158 → m[1][4] = 158、s[1][4] = 3，和手算一模一樣。

### 時間複雜度 Θ(n³)

兩種角度算出來一樣：

- **從子問題算**：子問題是所有 substring，約 n² 個；每個子問題跑最多 n 個 k，每個 k 常數時間，所以每個 O(n)。總共 n² × n = Θ(n³)。
- **從表算**：只填上半部，格數 1 + 2 + … + n = n(n+1)/2，約 n²（對角線全是 0，算不算進去都差不多）；每格最多試 n 個 k。n² × n，Θ(n³)。也有人寫 O(n³) 並強調它是上界：k 不是每格都有 n 個，細算會少一點。

比起暴力試大約 4ⁿ 種括法，好太多了。

> **陷阱** 兩個 n×n 矩陣直接相乘也是 n³，但那個 n 是**矩陣大小**；這裡的 n 是**矩陣個數**，兩者不同。

## 最佳二元搜尋樹 Optimal BST

### BST 怎麼搜尋：成功與失敗

要找東西，可以 linear search、binary search，也可以用二元樹。下面是一棵 binary search tree（BST，二元搜尋樹），每個節點放一個 key，最上面的 40 是 root：

```
            40
         /      \
       20        60
      /  \      /  \
    10    30  50    70
```

規則：**任何節點，左子樹都比它小、右子樹都比它大**。每個節點都要守規矩，例如 60：左邊 50 比它小、右邊 70 比它大。

這樣排的好處是搜尋很快。找 30：40 是 30 嗎？不是；30 比 40 小，只可能在左邊，右半邊整個不用看，往左到 20；30 比 20 大，往右；找到 30。比了 40、20、30 共 3 次，**比較次數就是搜尋的成本**。

- 每個 key 比幾次看它在第幾層：40 一次，20、60 兩次，最底下的四個三次。
- 最多比較次數就是樹高。所以樹越矮越快；排得平衡，高度大約 log n。
- 找得到叫 **successful search（成功搜尋）**，例如找 50：比 40 大往右，比 60 小往左，找到。
- 找不在樹裡的 9：比 40 小往左、比 20 小往左、比 10 小再往左，10 的左邊是空的（null），走到底了，9 不在樹裡。這叫 **unsuccessful search（失敗搜尋）**。失敗也要花比較：40、20、10 三次才確定找不到。
- 再找 47：比 40 大往右到 60，比 60 小往左到 50，比 50 小要往左，那裡是空的，又是一次失敗搜尋。找 45 也一樣。

### 方形節點：代表失敗的區間

在每個 null 的位置畫一個小方塊。放 key 的是一般節點（圓形），小方塊是另一種節點，裡面沒有 key，代表失敗搜尋：

- 找 11：比 40 小往左、比 20 小往左、比 10 大往右，停在 10 右邊的方塊。找 12 也停在同一個方塊。其實 11 到 19 之間任何數都停在這裡，所以這個方塊代表 **11～19 這一整段**。
- 最左邊的方塊代表 −∞～9（比 10 小的都一路往左停在這）；其他依序是 21～29、31～39、…；最右邊代表 71～+∞。
- 方塊其實就是 null：走到這裡就知道找不到了。

這種方塊叫 **dummy node**，也叫 **external node（外部節點）**。7 個 key 切出 8 段；**n 個 key 就有 n+1 個方塊**。

> **重點** 每個方塊代表一個區間的值，而不是單一值；每個 key 只代表一個值。

### 同樣的 key，很多棵 BST

只用 10、20、30，能排出幾種 BST？

```
①  10             ②  10             ③    20          ④    30           ⑤      30
     \                 \                /  \             /                   /
      20                30            10    30         10                  20
        \              /                                  \               /
         30          20                                    20           10
```

- ① 10、20、30 一路往右
- ② 10 當 root，30 在右，20 在 30 的左
- ③ 20 當 root，10 在左、30 在右（平衡）
- ④ 30 當 root，10 在左，20 在 10 的右
- ⑤ 30、20、10 一路往左

三個 key 一共 5 棵。n 個 key 的 BST 數量又是 Catalan 數 (2n 取 n)/(n+1)：n = 3 是 20/4 = 5，四個 key 有 14 棵。

如果每個 key 一樣常被找，成本看比較次數：root 1 次、第 2 層 2 次、第 3 層 3 次。

- ①②④⑤ 都是一、二、三層，平均 (1 + 2 + 3)/3 = 2 次。
- ③ 20 當 root：1 + 2 + 2 = 5，平均 5/3，比 2 小。

③ 最矮、左右平衡，叫 **height balanced BST**。反過來，7 個 key（10～70）若排成 70 → 60 → … → 10 一路往左的一長串，有 7 層，找最底下的 10 要比 7 次。結論：高度越小，比較越少。不過事情還沒完。

### 加上搜尋頻率

真正的 optimal BST 問題還要考慮每個 key **被搜尋的頻率**：有的很熱門，有的很冷門。成本改成「每個 key 的層數 × 頻率」再加總，熱門的放越深，成本越高。

> **例題** key 10、20、30 的搜尋頻率是 3、2、5。五棵樹的成本：
>
> | 樹 | 形狀 | 成本 |
> |---|---|---|
> | ① | 10 → 20 → 30 一路往右 | 1×3 + 2×2 + 3×5 = 22 |
> | ② | 10 root，30 在右，20 在 30 的左 | 1×3 + 2×5 + 3×2 = 19 |
> | ③ | 20 root，平衡 | 1×2 + 2×3 + 2×5 = 18 |
> | ④ | 30 root，10 在左，20 在 10 的右 | 1×5 + 2×3 + 3×2 = **17** |
> | ⑤ | 30 → 20 → 10 一路往左 | 1×5 + 2×2 + 3×3 = 18 |
>
> ④ 成本 17 最小，它就是 optimal BST：最熱門的 30 放 root，一下就找到。

> **陷阱** 平衡的那棵是 18，反而輸了。加了頻率，**最好的樹不一定最矮**。另外第一棵是 22（3 + 4 + 15），不是 18，這一步很容易算錯。

所以問題是：**給定 key 和頻率，找總成本最小的 BST**。

### 只考慮成功搜尋：公式

令 c(i,j) 是「第 i+1 到第 j 個 key」的最小成本，w(i,j) 是這些 key 的頻率總和。讓第 k 個 key 當 root：

```
c(i,i) = 0
c(i,j) = min { c(i,k−1) + c(k,j) } + w(i,j)，i < k ≤ j
w(i,j) = 第 i+1 到第 j 個 key 的頻率和
r(i,j) = 給出最小值的 k（這一段的 root）
```

為什麼要加 w？root 下面的左子樹、右子樹本來各自算好了成本，現在整段被掛到 root 底下，每個 key 都被往下推了一層、多比一次，多出來的剛好是整段的頻率總和；root 自己比 1 次，它的頻率也在 w 裡。

> **觀念** k 的範圍是 i < k ≤ j，從 i+1 開始，所以表格的 i 要從 0 開始編，key 卻從 1 開始編。這是為了配合公式，不是筆誤。

### 例題：key 10, 20, 30, 40，頻率 4, 2, 6, 3

> **例題** 四個 key 10、20、30、40，頻率 4、2、6、3（只有成功搜尋）。求最佳 BST 與成本。

**j−i = 0**：一個 key 都沒有，成本 0，對角線全是 0。

**j−i = 1**：每次只看一個 key。c(0,1) 只有 key 1（10），它當 root 比 1 次，成本 1×4 = 4，root 記 1。同理 c(1,2) = 2、c(2,3) = 6、c(3,4) = 3：**一個 key 的成本就是它的頻率**。

**j−i = 2**：每次看兩個 key。先直接算，再用公式驗證。

c(0,2)：key 10、20，頻率 4、2，w(0,2) = 6。

| root | 直接算 | 用公式 |
|---|---|---|
| 10（k=1） | 4×1 + 2×2 = **8** | c(0,0) + c(1,2) + w(0,2) = 0 + 2 + 6 = 8 |
| 20（k=2） | 2×1 + 4×2 = 10 | c(0,1) + c(2,2) + w(0,2) = 4 + 0 + 6 = 10 |

兩種算法一樣，公式成立。c(0,2) = 8，r(0,2) = 1。

c(1,3)：key 20、30（頻率 2、6）。20 當 root：1×2 + 2×6 = 14；30 當 root：1×6 + 2×2 = 10。c(1,3) = 10，r(1,3) = 3。

c(2,4)：key 30、40（頻率 6、3）。30 當 root：1×6 + 2×3 = 12；40 當 root：1×3 + 2×6 = 15。c(2,4) = 12，r(2,4) = 3。

**j−i = 3**：三個 key 有 5 棵樹，不再一棵一棵算，直接用公式。

| 格子 | w | k=… 的 c(i,k−1) + c(k,j) | 最小 | c | r |
|---|---|---|---|---|---|
| c(0,3) | 4+2+6 = 12 | k=1：0 + 10 = 10；k=2：4 + 6 = 10；k=3：8 + 0 = 8 | 8 | 20 | 3 |
| c(1,4) | 2+6+3 = 11 | k=2：0 + 12 = 12；k=3：2 + 3 = 5；k=4：10 + 0 = 10 | 5 | 16 | 3 |

**j−i = 4**：w(0,4) = 4 + 2 + 6 + 3 = 15。

| k（root） | c(i,k−1) + c(k,j) | 值 |
|---|---|---|
| 1（10） | c(0,0) + c(1,4) = 0 + 16 | 16 |
| 2（20） | c(0,1) + c(2,4) = 4 + 12 | 16 |
| 3（30） | c(0,2) + c(3,4) = 8 + 3 | **11** |
| 4（40） | c(0,3) + c(4,4) = 20 + 0 | 20 |

c(0,4) = 11 + 15 = **26**，r(0,4) = 3。

```
c / r 表（i 是列、j 是行）
       j=0   j=1   j=2    j=3    j=4
i=0    0     4/1   8/1   20/3   26/3
i=1          0     2/2   10/3   16/3
i=2                0      6/3   12/3
i=3                       0      3/4
i=4                              0
```

**用 r 表建樹**：

1. r(0,4) = 3：3 是 key 的**編號**，第 3 個 key 是 30，當整棵樹的 root。root 是 k 時，左邊看 (i, k−1)、右邊看 (k, j)：左 (0,2)、右 (3,4)。
2. r(0,2) = 1：10 放在 30 的左邊；10 的右邊看 (1,2)，r(1,2) = 2，是 20。
3. r(3,4) = 4：40 放在 30 的右邊。

```
          30
        /    \
      10      40
        \
         20
```

驗算：30 在第 1 層 1×6、10 和 40 在第 2 層 2×4 + 2×3、20 在第 3 層 3×2，合計 6 + 8 + 6 + 6 = 26。

### 加上失敗搜尋：成功機率 p、失敗機率 q

升級版：同時考慮成功和失敗搜尋。還是 10、20、30、40 四個 key，key 之間插入代表失敗區間的方塊，n 個 key 把數線切成 n+1 段，所以有 5 個方塊。

> **比喻** 開一家小店，門口有櫃台、後面有倉庫。櫃台上的伸手就拿到，倉庫裡的要走過去，比較花時間。所以常賣的放櫃台、少賣的放倉庫。對應到 BST：key 是商品，常被找的放靠近 root，就像櫃台。
>
> 還有一種情況：客人要的東西店裡根本沒有。「被問但沒有」也有頻率，就是失敗搜尋的機率。常被問的缺貨品，如果每次都要跑倉庫找半天才說沒有，多浪費；最好一下就能回答「沒有」。所以成功、失敗的機率都重要。

把頻率換成比例就是機率，寫成小數，全部加起來等於 1：

- 成功機率照 key 的順序叫 p₁…pₙ，p₁ 是搜尋第 1 個 key（10）的機率。
- 失敗機率多一個，從 0 開始：q₀…qₙ。q₀ 是要找的值比 10 還小的機率，q₄ 是比 40 還大的機率。
- 每個 q 代表一整段值，每個 p 只代表一個 key。

### 一棵樹的期望成本

> **例題** p₁…p₄ = 0.1, 0.2, 0.1, 0.2（合計 0.6），q₀…q₄ = 0.1, 0.05, 0.15, 0.05, 0.05（合計 0.4）。樹：20 當 root，10、30 在下一層，40 在 30 的右下；方塊 E₀…E₄ 是失敗節點。
>
> ```
>               20                 level 1
>             /    \
>           10      30             level 2
>          /  \    /  \
>        E0   E1  E2   40          level 3
>                     /  \
>                   E3    E4       level 4
> ```
>
> - key：20 比 1 次 1×0.2；10、30 在 level 2，各 2×0.1；40 在 level 3，3×0.2。合計 0.2 + 0.2 + 0.2 + 0.6 = 1.2。
> - 方塊：E₀ 畫在 level 3，但我們不會在 E₀ 比較：比完 10、發現左邊空了，就知道找不到。所以方塊算 **level − 1**。E₀、E₁、E₂ 是 2×0.1、2×0.05、2×0.15；E₃、E₄ 在 level 4，各 3×0.05。合計 0.2 + 0.1 + 0.3 + 0.15 + 0.15 = 0.9。
> - 期望成本 = 1.2 + 0.9 = **2.1**。

```
cost(T) = Σ(i=1..n) pᵢ × level(aᵢ)  +  Σ(i=0..n) qᵢ × (level(Eᵢ) − 1)
```

key 從 1 加到 n，方塊比 key 多一個，從 0 加到 n。

> **陷阱** 上面是 Horowitz 教科書的算法：方塊算 level − 1。CLRS 把走到 dummy key 也算一次比較，方塊算 level 而不是 level − 1，數字會不同。作答要看題目採用哪種定義。另外 E₃、E₄ 在 level 4，貢獻是 3×0.05，不是 4×0.05。

### Optimal BST：暴力法試不完

這是「有了樹、算成本」。反過來：已知 key 和 p、q，找**期望成本最小**的樹。剛才那棵是 2.1，能不能更小？成本取決於形狀：root 換成 30 或 40，每個 key 的層數都跟著變。四個 key 有 14 棵 BST，每棵成本不同；最直接是 14 棵全畫出來各算成本，挑最小。但棵數照 Catalan 數暴增，40 個 key 大約 2.6 × 10²¹ 棵，一棵一棵試根本做不完。DP 也等於試過所有可能，但它是**間接地**試，不用真的畫出每棵樹。

公式跟只有成功搜尋時長得一樣，只是 w 改成這一段所有 p 和 q 的總和（weight）：

```
w(i,i) = qᵢ
w(i,j) = q_i + Σ(l=i+1..j) (p_l + q_l) = w(i,j−1) + p_j + q_j
c(i,i) = 0，r(i,i) = 0
c(i,j) = min { c(i,k−1) + c(k,j) } + w(i,j)，i < k ≤ j
r(i,j) = 給出最小值的 k
```

例如 w(0,2) = q₀ + p₁ + q₁ + p₂ + q₂；w(0,3) 前面完全一樣，只多了 p₃ 和 q₃。所以 **w(i,j) = w(i,j−1) + pⱼ + qⱼ**，上一格加一點就好，不用從頭加。

先試展開 c(0,3)：k 可以是 1、2、3，三項 c(0,0)+c(1,3)、c(0,1)+c(2,3)、c(0,2)+c(3,3) 取最小再加 w(0,3)。c(0,0)、c(3,3) 沒有 key，是 0；c(1,3) 不知道，只好再展開（k = 2 或 3），越展越多，而且像 c(2,3) 這種子問題一再出現。範圍越來越小：0～3 變 1～3。要知道大的，得先知道小的，這正是 DP。所以順序跟矩陣連乘一樣：j−i = 0、1、2、3，一條一條算，而且每格要算三個值：**cost、weight、root**。

### 例題：p = 3, 3, 1, 1；q = 2, 3, 1, 1, 1

> **例題** key 10、20、30、40。成功的 p₁…p₄ = 3, 3, 1, 1；失敗的 q₀…q₄ = 2, 3, 1, 1, 1。本來是小數，全部乘了 16（總和剛好 16），變整數好算，最後答案要除回 16。求最佳 BST。

**第一步：填 w。** w(i,i) = qᵢ；往上每格 = 下面那格 + 新的 p、q。

| j−i | w |
|---|---|
| 0 | w(0,0) = 2，w(1,1) = 3，w(2,2) = 1，w(3,3) = 1，w(4,4) = 1 |
| 1 | w(0,1) = 2 + 3 + 3 = 8，w(1,2) = 3 + 3 + 1 = 7，w(2,3) = 1 + 1 + 1 = 3，w(3,4) = 1 + 1 + 1 = 3 |
| 2 | w(0,2) = 8 + 3 + 1 = 12，w(1,3) = 7 + 1 + 1 = 9，w(2,4) = 3 + 1 + 1 = 5 |
| 3 | w(0,3) = 12 + 1 + 1 = 14，w(1,4) = 9 + 1 + 1 = 11 |
| 4 | w(0,4) = 14 + 1 + 1 = 16（全部機率 × 16 的總和） |

c(i,i) 要 i < k ≤ i，找不到 k，沒有 key，成本 0；沒有 key 也沒有 root，r 寫 0。

**j−i = 1：c 就是 w。** c(0,1)：k 只有 1，c(0,0) + c(1,1) + w(0,1) = 0 + 0 + 8 = 8。只有一個 k、兩邊都是 0，所以 c 就等於 w：c(1,2) = 7、c(2,3) = 3、c(3,4) = 3；root 就是那個 k：1、2、3、4。

**j−i = 2：**

| 格子 | w | 候選 | c | r |
|---|---|---|---|---|
| c(0,2) | 12 | k=1：c(0,0) + c(1,2) = 0 + 7 = 7；k=2：c(0,1) + c(2,2) = 8 + 0 = 8 | 7 + 12 = 19 | 1 |
| c(1,3) | 9 | k=2：c(1,1) + c(2,3) = 0 + 3 = 3；k=3：c(1,2) + c(3,3) = 7 + 0 = 7 | 3 + 9 = 12 | 2 |
| c(2,4) | 5 | k=3：c(2,2) + c(3,4) = 0 + 3 = 3；k=4：c(2,3) + c(4,4) = 3 + 0 = 3 | 3 + 5 = 8 | 3 |

誰給出最小值，就記下誰；大部分 DP 題都這樣。c(2,4) 兩個 k 平手，取 k = 3（取 4 也一樣是最佳解）。

**j−i = 3：**

| 格子 | w | 候選 | c | r |
|---|---|---|---|---|
| c(0,3) | 14 | k=1：0 + 12 = 12；k=2：8 + 3 = 11；k=3：19 + 0 = 19 | 11 + 14 = 25 | 2 |
| c(1,4) | 11 | k=2：0 + 8 = 8；k=3：7 + 3 = 10；k=4：12 + 0 = 12 | 8 + 11 = 19 | 2 |

注意 c(1,4) 的 k 從 2 開始試，因為 k 要大於 i = 1。

**j−i = 4：** w(0,4) = 16。

| k | c(0,k−1) + c(k,4) | 值 |
|---|---|---|
| 1 | c(0,0) + c(1,4) = 0 + 19 | 19 |
| 2 | c(0,1) + c(2,4) = 8 + 8 | **16** |
| 3 | c(0,2) + c(3,4) = 19 + 3 | 22 |
| 4 | c(0,3) + c(4,4) = 25 + 0 | 25 |

c(0,4) = 16 + 16 = **32**，r(0,4) = 2。

完整的表（每格 w / c / r）：

```
j−i=4   w=16 c=32 r=2
j−i=3   w=14 c=25 r=2   w=11 c=19 r=2
j−i=2   w=12 c=19 r=1   w=9  c=12 r=2   w=5 c=8 r=3

        i=0             i=1             i=2           i=3           i=4
```

我們從最小的格子一列一列往上算，算大格子時小格子早就在表裡。這種由小到大填表叫 **tabular approach**，是 DP 的典型做法。每格都取最小，等於每段都試過所有 root，也就間接試過所有樹。

> **陷阱** 機率乘過 16，真正的最小期望成本是 32 ÷ 16 = **2**，不是 32。

**建出最佳 BST**：r(0,4) 管 key 1～4（i 從 0 開始是為了配合 q₀）。

1. r(0,4) = 2：第 2 個 key 20 當 root；k = 2，左邊 (0,1)、右邊 (2,4)。
2. r(0,1) = 1：10 放在 20 的左邊，左邊結束。
3. r(2,4) = 3：30 放在 20 的右邊；30 的右邊看 (3,4)，r(3,4) = 4，是 40。

```
        20
       /  \
     10    30
             \
              40
```

其他空位就是代表失敗的方塊。驗算（level − 1 的算法）：key 1×3 + 2×3 + 2×1 + 3×1 = 14；方塊 E₀、E₁、E₂ 在 level 3：2×2 + 2×3 + 2×1 = 12，E₃、E₄ 在 level 4：3×1 + 3×1 = 6；合計 14 + 12 + 6 = 32。

> **重點** 兩個例題方法完全一樣，差別只在 w 有沒有把失敗機率 q 算進去。只有成功搜尋時，w(i,j) 是 key 頻率和；有失敗搜尋時，w(i,j) = qᵢ + Σ(pₗ + qₗ)。

```python
# Optimal BST：p[1..n] 成功、q[0..n] 失敗（只有成功搜尋時 q 全設 0）
def optimal_bst(p, q, n):
    w = [[0] * (n + 1) for _ in range(n + 1)]
    c = [[0] * (n + 1) for _ in range(n + 1)]
    r = [[0] * (n + 1) for _ in range(n + 1)]
    for i in range(n + 1):
        w[i][i] = q[i]
    for d in range(1, n + 1):               # d = j - i
        for i in range(0, n - d + 1):
            j = i + d
            w[i][j] = w[i][j - 1] + p[j] + q[j]
            best, root = None, None
            for k in range(i + 1, j + 1):   # i < k <= j
                v = c[i][k - 1] + c[k][j]
                if best is None or v < best:
                    best, root = v, k
            c[i][j] = best + w[i][j]
            r[i][j] = root
    return c[0][n], r
```

時間：表約 n² 格，每格試最多 n 個 root，O(n³)，跟矩陣連乘同一型。

## 可靠度設計 Reliability Design

### 串聯系統的可靠度

要架一個系統，從左邊進、右邊出，中間每個裝置都正常才算成功。系統由裝置 D₁、D₂、D₃、D₄ 一個接一個排成（例如一間錄影室要用到白板、相機、燈、筆，任何一個出事錄影就得停）。

- 每個裝置要花錢，價格叫 **cost**：c₁、c₂、…
- 每個裝置有 **reliability（可靠度）**，就是正常運作的機率。白板很可靠，燈會壞，筆會乾掉。

假設每個都是 0.9。串聯要全部正常，所以相乘：0.9 × 0.9 × 0.9 × 0.9 = 0.6561。每個都 0.9，整個系統卻只剩 0.65 左右，大約 35% 會失敗。目標：讓整個系統的 reliability 越高越好。

### 一個 stage 放多份：並聯

怎麼提高？每種多準備幾份，一台相機壞了馬上換另一台，系統就不會停。

- 不同裝置之間是**串聯（series）**；同一種的幾份是**並聯（parallel）**，只要一份正常就好。
- 同一種裝置的那一組叫一個 **stage**。stage 裡一份在工作，其他當 backup，壞了就接手。

> **例題** stage 放 3 份 reliability 0.9 的 D₁，可靠度多少？
> 一份壞掉的機率是 1 − 0.9 = 0.1；stage 失敗代表 3 份全壞：0.1³ = 0.001。所以 stage 正常是 1 − 0.001 = 0.999，從 0.9 拉到 0.999。

```
stage i 放 mᵢ 份、每份可靠度 rᵢ：  φᵢ(mᵢ) = 1 − (1 − rᵢ)^mᵢ
系統可靠度 = ∏ φᵢ(mᵢ)，總花費 = Σ cᵢ·mᵢ ≤ C
```

副本越多越可靠，但要花錢。錢有限，就要決定每種買幾份最划算。

### 問題與上限 uᵢ

**問題**：手上總共 C 元，在預算內每種裝置各買幾份，讓系統 reliability 最大？

> **例題** 三種裝置，cost 30、15、20 元，reliability 0.9、0.8、0.5，預算 C = 105。

先算每種最多能買幾份（上限 uᵢ）。每種至少要 1 份，不然系統少一環：30 + 15 + 20 = 65 元；105 − 65 = 40 元可以拿來買副本。

```
uᵢ = ⌊(C − Σ cⱼ) / cᵢ⌋ + 1
u₁ = ⌊40 / 30⌋ + 1 = 1 + 1 = 2
u₂ = ⌊40 / 15⌋ + 1 = 2 + 1 = 3
u₃ = ⌊40 / 20⌋ + 1 = 2 + 1 = 3
```

### 集合法：一步加一種裝置

解法跟 0/1 knapsack 的集合法（sets method）一樣：一步加一種裝置，把可能的選擇列成集合。集合裡每一項是一個有序對 **(reliability, cost)**：目前的可靠度和花了多少錢。

**S⁰ = {(1, 0)}**：什麼都還沒買。reliability 從 1 開始，因為之後要一直乘，從 0 開始乘什麼都是 0。

**D₁（0.9，30 元，最多 2 份）**：

- 1 份：可靠度 0.9、30 元 → (0.9, 30)。
- 2 份：1 − 0.1² = 0.99、60 元 → (0.99, 60)。
- S¹ = {(0.9, 30), (0.99, 60)}。

**D₂（0.8，15 元，最多 3 份）**：每種份數都要跟 S¹ 的每一對組合（可靠度相乘、錢相加）。

| D₂ 份數 | stage 可靠度、花費 | 配 (0.9, 30) | 配 (0.99, 60) |
|---|---|---|---|
| 1 | 0.8，15 | (0.72, 45) | (0.792, 75) |
| 2 | 1 − 0.2² = 0.96，30 | (0.864, 60) | (0.9504, 90) 不可行 |
| 3 | 1 − 0.2³ = 0.992，45 | (0.8928, 75) | 105 元，不可行 |

花到 90 只剩 15 元，買不起一份 20 元的 D₃；花到 105 錢就光了。這些不可行，刪掉。所以之後先看錢：**錢不夠，可靠度連算都不用算**。

### Dominance rule（支配規則）

D₂ 處理完得到 4 對：(0.72, 45)、(0.792, 75)、(0.864, 60)、(0.8928, 75)。照理說多花錢應該更可靠。可是 (0.864, 60) 比 (0.792, 75) 更可靠、還更便宜，那 (0.792, 75) 就是又貴又不可靠。

> **重點** Dominance rule：如果 (r₁, c₁) 和 (r₂, c₂) 滿足 r₁ ≤ r₂ 且 c₁ ≥ c₂，就說前者被支配（dominated），刪掉它。依 cost 排好之後，reliability 也必須跟著遞增。

S² = {(0.72, 45), (0.864, 60), (0.8928, 75)}。

**D₃（0.5，20 元，最多 3 份）**：

| D₃ 份數 | stage 可靠度、花費 | 配 (0.72, 45) | 配 (0.864, 60) | 配 (0.8928, 75) |
|---|---|---|---|---|
| 1 | 0.5，20 | (0.36, 65) | (0.432, 80) | (0.4464, 95) |
| 2 | 1 − 0.5² = 0.75，40 | (0.54, 85) | (0.648, 100) | 115 元，超過 |
| 3 | 1 − 0.5³ = 0.875，60 | (0.63, 105) | 120 元，超過 | 135 元，超過 |

> **陷阱** D₃ 的 reliability 是 0.5，兩份是 1 − 0.5² = 0.75；別誤用 0.9。

### 合併並刪掉被支配的（merge and purge）

把 D₃ 的結果合併成 S³，依 cost 排好，同時刪掉被支配的：

| 有序對 | 判斷 |
|---|---|
| (0.36, 65) | 保留 |
| (0.432, 80) | 保留 |
| (0.54, 85) | 保留 |
| (0.4464, 95) | 刪：(0.54, 85) 更可靠又更便宜 |
| (0.648, 100) | 保留 |
| (0.63, 105) | 刪：(0.648, 100) 更可靠又更便宜 |

S³ 剩 4 對，可靠度最高的是 **(0.648, 100)**，在預算內，這就是答案。

### 回溯：每種買幾份

光知道 0.648 還不夠，要知道每種買幾份，從答案往回找：

1. (0.648, 100) 是在「D₃ 買 2 份」那一列算出來的：它是 (0.864, 60) × 0.75、+40 元。
2. 回 S² 找 (0.864, 60)：它是「D₂ 買 2 份」來的，來自 S¹ 的 (0.9, 30)。
3. (0.9, 30) 是 D₁ 只買 1 份。

答案：**D₁ 一份、D₂ 兩份、D₃ 兩份**。驗算：0.9 × 0.96 × 0.75 = 0.648，30 + 30 + 40 = 100 ≤ 105。

> **觀念** 本質上就是 0/1 knapsack 的集合法，只是「加價值」換成「乘可靠度」，而且每一步有好幾種份數可選。

## 編輯距離 Edit Distance

### 問題：插入、刪除、取代

給兩個字串 x 和 y，要用最便宜的方法把 x 變成 y。允許三種字元編輯：

1. **插入（insert）**：在任何位置插入一個字元。
2. **刪除（delete）**：刪掉任何一個字元。
3. **取代（replace）**：把字元 c 換成 c′，例如 CAT 的 A 換成 U 變成 CUT。

取代也能用「刪掉再插入」做到，但成本是題目給的，可能依字元不同；題目會給一張表，每個字母插入、刪除多少，A 換成 B 又多少，取代可能比刪掉再插入便宜。

應用：

- **拼字校正**：按了 A，其實可能想按旁邊的 S。把成本設成「這種錯有多不可能」，總成本最小就是最可能發生的那組錯誤；打出來的字跟字典裡每個字都算一次，就知道你最可能想打哪個字。
- **比對 DNA**：DNA 會突變，而 C 變 G 比 C 變 A 常見，所以前者成本低、後者高。這樣算出的 edit distance 衡量兩段 DNA 在演化上有多接近。

### LCS 是 edit distance 的特例

edit distance 還包住另一個經典：**LCS（longest common subsequence，最長共同子序列）**：從兩個字串各刪掉一些字母（可以跳著刪），讓剩下的一模一樣，而且越長越好。

> **例題** HIEROGLYPHOLOGY 和 MICHELANGELO 的 LCS 是 **HELLO**（長度 5）。

化成 edit distance：

- 插入、刪除成本都設 1。
- 取代：同一個字母換成自己成本 0；不同字母成本 ∞，等於不准換。

這樣算出來的就是「最少要幾次插入和刪除」，也就是兩邊總共刪掉最少的字母，剩下的就是共同子序列。最小成本 = |x| + |y| − 2·LCS 長度；這個例子是 15 + 12 − 2×5 = 17。解更一般的問題反而容易，還順便解掉 LCS。

### 子問題與三種猜法

現在有兩個字串，就同時對 x 和 y 用 suffix：

- **子問題**：DP(i, j) = 把 x[i:] 變成 y[j:] 的最小成本，所有 i、j 組合都要。i 有 |x|+1 種、j 有 |y|+1 種，子問題約 |x|·|y| 個；長度都是 n 就是 n²。
- **猜**：一直從前面切，所以看兩邊的第一個字元 x[i]、y[j]。處理它們只有三種方式：
  - 取代：x[i] 換成 y[j]，兩邊第一個都處理掉 → (i+1, j+1)。
  - 插入：在最前面插入 y[j]，y 少一個、x 還從 i 開始 → (i, j+1)。
  - 刪除：刪掉 x[i]，x 從 i+1 開始、y 不動 → (i+1, j)。

為什麼三種就涵蓋所有可能？最佳解一定要做出 y 的第一個字元：不是 x[i] 取代來的，就是插入來的；要是晚點才插入，x[i] 就得先被刪掉。

```
DP(i, j) = min( replace(x[i] → y[j]) + DP(i+1, j+1),
                insert(y[j])         + DP(i,   j+1),
                delete(x[i])         + DP(i+1, j  ) )
base case：DP(|x|, |y|) = 0
原問題：DP(0, 0)
```

> **陷阱** 這裡 DP(i, j) 的 i、j 是**兩個 suffix 各自的起點**，不是一個 substring 的頭尾。

每個選項至少讓一個字串前進一格，一定有進度，不會繞圈（acyclic）。拓撲順序：都是 suffix，從尾巴往前算，外層 i 從 |x| 倒數到 0，內層 j 從 |y| 倒數到 0。

### 二維表與 DAG

這個 DP 可以看成 DAG 上的最短路徑，最好畫成二維表：i 從 0 到 |x|、j 從 0 到 |y|，每一格是一個子問題 DP(i, j)，它依賴**右邊、下面、右下**三格。一列一列從下往上算可以；斜著算、一行一行倒著算也行，只要一路往原點推進。原問題 DP(0, 0) 是表的左上角。DAG 上每條邊的權重就是操作成本：往右是插入、往下是刪除、斜的是取代。從右下角跑最短路徑到左上角就是答案，直接跑 for 迴圈也一樣。

> **例題** x = GATTA、y = CATT，插入、刪除成本 1，取代：相同字母 0、不同字母 1。DP(i, j) 表（列 i 是 x[i:]，行 j 是 y[j:]）：
>
> | | j=0 CATT | j=1 ATT | j=2 TT | j=3 T | j=4 空 |
> |---|---|---|---|---|---|
> | i=0 GATTA | **2** | 2 | 3 | 4 | 5 |
> | i=1 ATTA | 2 | 1 | 2 | 3 | 4 |
> | i=2 TTA | 3 | 2 | 1 | 2 | 3 |
> | i=3 TA | 3 | 2 | 1 | 1 | 2 |
> | i=4 A | 3 | 2 | 2 | 1 | 1 |
> | i=5 空 | 4 | 3 | 2 | 1 | 0 |
>
> - 最後一列：x 已空，只能把 y 剩下的全插入，4、3、2、1、0。最後一行：y 已空，只能把 x 剩下的全刪除，5、4、3、2、1、0。
> - DP(4, 3)：A 變 T，取代 1 + DP(5,4) = 1；插入 1 + DP(4,4) = 2；刪除 1 + DP(5,3) = 2 → 1。
> - DP(0, 0)：G 換 C 是 1 + DP(1,1) = 2；插入 C 是 1 + DP(0,1) = 3；刪除 G 是 1 + DP(1,0) = 3 → **2**。
> - 對應的編輯：G 取代成 C，ATT 原樣保留，刪掉最後的 A，共 2。

```python
def edit_distance(x, y, ins, dele, rep):
    n, m = len(x), len(y)
    DP = [[0] * (m + 1) for _ in range(n + 1)]
    for i in reversed(range(n + 1)):
        for j in reversed(range(m + 1)):
            if i == n and j == m:
                continue                       # base case 0
            best = float('inf')
            if i < n and j < m:
                best = min(best, rep(x[i], y[j]) + DP[i + 1][j + 1])
            if j < m:
                best = min(best, ins(y[j]) + DP[i][j + 1])
            if i < n:
                best = min(best, dele(x[i]) + DP[i + 1][j])
            DP[i][j] = best
    return DP[0][0]
```

### 執行時間

子問題 |x|·|y| 個，每個只看三個選項、查表常數時間 O(1)，總共 **Θ(|x|·|y|)**。這是目前已知最好的；能不能更快是一個大大的 open problem。空間可以省：只存最後一列（下一列），線性空間就夠，時間還是平方。

## 背包問題 Knapsack

### 問題設定

這題離開字串，不過等一下會發現還是藏著一個序列。

> **比喻** 你要去背包旅行，背包容量有限（這裡看大小，換成重量也一樣），想帶的東西太多，全帶塞不下。

- 每個物品 i 有大小 sᵢ 和價值 vᵢ（價值就是你有多需要它）。
- **大小必須是整數**，這個假設很重要，沒有它這方法就不行。
- 背包總大小是 S。選一個子集合，總大小 ≤ S（一定要裝得下，不能作弊），讓價值總和最大。

### 只用 suffix 會錯

物品排成一排（順序不重要，隨便排），用物品的 suffix 當子問題：DP(i) = 從物品 i 到最後能拿的最大價值。猜：物品 i 放不放，只有兩種。想寫成 DP(i) = max(DP(i+1), DP(i+1) + vᵢ)。

> **陷阱** 這個式子是錯的：放進物品 i 會用掉 sᵢ，但 DP(i+1) 不知道容量已經用掉多少，式子裡根本沒有 S，它會永遠選「全放」。

### 修正：子問題多記剩餘容量

讓子問題多帶一點資訊：**DP(i, X) = 從物品 i 開始、背包還剩 X 的容量時，能拿的最大價值**。X 是 0 到 S 的整數，所以子問題共 n·(S+1) 個。

```
DP(i, X) = max( DP(i+1, X),                 ← 不放物品 i，容量不變
                DP(i+1, X − sᵢ) + vᵢ )      ← 放物品 i（只有 sᵢ ≤ X 時才可以）
base case：DP(n, X) = 0
原問題：DP(0, S)
```

> **陷阱** 「放」這個選項只有在 sᵢ ≤ X 時才合法，容量不能變成負的；寫程式時要記得檢查。

> **例題** 3 個物品：s = 2, 3, 4；v = 3, 4, 5；S = 5。由下往上（i 由大到小）填 DP(i, X)：
>
> | i（可用的物品） | X=0 | X=1 | X=2 | X=3 | X=4 | X=5 |
> |---|---|---|---|---|---|---|
> | 3（沒有物品） | 0 | 0 | 0 | 0 | 0 | 0 |
> | 2（物品 3：s=4, v=5） | 0 | 0 | 0 | 0 | 5 | 5 |
> | 1（物品 2、3） | 0 | 0 | 0 | 4 | 5 | 5 |
> | 0（物品 1、2、3） | 0 | 0 | 3 | 4 | 5 | **7** |
>
> （物品編號 1、2、3 對應 i = 0、1、2。）DP(0, 5) = max(DP(1, 5), DP(1, 3) + 3) = max(5, 4 + 3) = 7。DP(1, 3) = 4 是放物品 2（DP(2, 0) + 4）。答案：放物品 1 和 2，大小 2 + 3 = 5，價值 3 + 4 = 7。

### Pseudo-polynomial 時間

每個子問題一個 max，常數時間，總共 **O(n·S)**。這是多項式時間嗎？**不是**。

- 多項式時間的意思是對輸入的「大小」是多項式。數字用二進位寫，S 只要大約 log S 個 bit，輸入大小大約 n·log S。
- 可是 S = 2^(log S)，對 bit 數來說是指數。k 個 bit 能寫出 2ᵏ 那麼大的數。
- 不過 S 不大時其實還好。這種叫 **pseudo-polynomial（偽多項式）**：對輸入大小 n，以及輸入裡出現的整數（像 S），都是多項式。n·S 是 n 和 S 的乘積，可以叫它「偽二次」。

> **重點** 口訣：多項式好、指數壞、偽多項式還可以。偽多項式介於多項式和指數之間。對 knapsack 來說，偽多項式已經是能期待的最好結果（它是 NP-complete 問題）。

## 第二種猜：讓子問題多記一點

把 knapsack 的這招提升成一個新觀念：

- **第一種猜**：遞迴式裡有好幾個選項，取 min 或 max。例如不知道往左還往右，就兩個都試、挑好的；換句話說，是在猜「要用哪些子問題拼出答案」。之前每個 DP 都用過，只有 Fibonacci 不用，因為它的遞迴式是固定的。
- **第二種猜**：更高一層。定義子問題時就多放參數，讓子問題**記住解的更多特徵**。

knapsack 已經偷偷用過第二種猜：只記 suffix 不夠，不知道前面跳過的物品裝了哪些，更要緊的是不知道用掉多少容量，判斷不了物品 i 放不放得下。所以每個 suffix 再配上剩餘容量 X，子問題變成 S+1 倍：同一個 suffix 解很多次，大背包、小背包、容量 0，全都算好。從猜的角度看，就是讓子問題多記住一些「過去」。

> **重點** 直覺的子問題不夠用時，就把缺的資訊加進子問題。口號：**more subproblems, more power**。接下來每個例子都是這一型。

## 指法問題 Piano／Guitar Fingering

### 問題與難度函數 d

給一首曲子，也就是一串音，要決定彈每個音用哪根手指。鋼琴有一整排鍵（像只有一排的電腦鍵盤），按一個鍵發一個音，從電腦的角度看很單純；麻煩在於同一個鍵可以用任何一根手指按。彈一個音無所謂，彈一長串時，有些換法很順，有些很彆扭。

- 輸入：n 個音，要替每個音指定一根手指。手指編號 1 到 F，單手 F = 5、雙手 10。先看右手、一次只彈一個音。
- 難度函數 **d(p, f, q, g)**：現在用手指 f 彈音 p，下一個音 q 改用手指 g，有多難。

d 可以反映的規則：

- **stretch**：p、q 離很遠，手要撐開，最好用相距遠的手指，不然 d 很大。
- **legato（連奏）**：同一根手指不能連按兩個不同的鍵，f = g 時 p 必須等於 q。
- **weak finger rule（弱指規則）**：3、4 指之間的切換特別彆扭，盡量避免。

d 其實就是一張大表，填你覺得順手的數字；怎麼填是音樂理論家的研究題目。

> **比喻** 彈吉他時真的要想哪根手指按哪一格：開頭幾個空弦音不用按，最簡單；第 5 弦第 1 格用食指（大家都最愛食指）；下一個音在最粗的第 6 弦第 3 格，習慣用中指，說不出為什麼，就是順。試過很多指法後覺得最舒服的那組，那種「舒服程度」就是 d 要量的。如果小指按在上面，其他手指就很難伸到下面的弦；這些難不難，都可以照自己的感覺寫進 d。

### 只猜這個音的手指：寫不出來

1. 子問題：輸入是序列，候選是 prefix、suffix、substring。選 suffix：從第 i 個音開始，後面全部怎麼彈（從左往右彈，彈掉前面的，剩下永遠是 suffix）。
2. 猜：最明顯的是「第 i 個音用哪根手指」，每根都試。
3. 遞迴式（第一個會想到、但是錯的寫法）：DP(i) = min over f ( DP(i+1) + 第 i 個音換到第 i+1 個音的 d )。

> **陷阱** 寫不出來：d 要知道第 i+1 個音用哪根手指，DP(i+1) 沒告訴我們。簡單的 DP 猜一件事就夠，這題需要多知道一點。

### DP(i, f)：讓子問題記住手指

把第 i 個音的手指也放進子問題：**DP(i, f) = 從第 i 個音彈到最後的最小難度，已知第 i 個音用手指 f**。本來要猜的，現在別人告訴你了。

那現在猜什麼？這是最難想的一步：**猜下一個音用哪根手指 g**。子問題有兩個參數，下一個子問題也要給兩個參數 DP(i+1, g)，每個 g 都試：

```
DP(i, f) = min over g ( d(note[i], f, note[i+1], g) + DP(i+1, g) )
base case：DP(n−1, f) = 0
原問題：min over f DP(0, f)
```

先付轉換成本（第 i 個音用 f 換到第 i+1 個音用 g 有多難），剩下的交給 DP(i+1, g)，它已經知道第 i+1 個音用 g。這就是多定義子問題的魔力：子問題自己記住手指在哪，轉換成本就算得出來。

```python
for i in reversed(range(n - 1)):      # 外層：音，由右往左（suffix 短的先算）
    for f in range(1, F + 1):         # 內層：手指，把這一欄填好再往左一欄
        DP[i][f] = min(d(note[i], f, note[i + 1], g) + DP[i + 1][g]
                       for g in range(1, F + 1))
answer = min(DP[0][f] for f in range(1, F + 1))
```

> **陷阱** 兩層迴圈不能對調。若外層是 f、內層是 i，算 DP(i, f) 時還會用到下一欄尚未算好的 DP(i+1, g)（g > f）。i 一定要在外層、由右往左。

### 原問題與 DAG 觀點

原問題不是任何一個子問題：DP(0, f) 一定要給一根手指，但第一個音用哪根我們不知道。簡單：每根手指都當開頭試，答案是所有 DP(0, f) 取最小。這裡沒有轉換成本，因為彈第一個音之前手指不在任何地方。

換成 DAG 看：橫軸是第 i 個音、縱軸是手指 1 到 F，每格一個點。從「第 i 個音用手指 f」出發，下一個音用 1～F 各有一條邊；相鄰兩欄全部互連，叫 **complete bipartite graph（完全二分圖）**，邊的權重就是 d。在這個 DAG 上找最短路徑，就是這個 DP 在做的事。但沒有單一起點：加一個 source，用權重 0 的邊連到第 0 欄每個點，再跑單源最短路徑，路徑經過的點就告訴你每個音用哪根手指。加 source 跟「每根手指試一次取 min」是同一件事。

### 時間 Θ(nF²)

子問題 n·F 個；每個子問題猜下一根手指 F 種，查 d 表常數時間，每個 Θ(F)。總時間 **Θ(n·F²)**。F 只有 5，幾乎是線性，很好的演算法。

### 推廣一：吉他上同一個音有好幾種彈法

吉他有 6 條弦，同一個音不只一種彈法，可以換弦換格（例如第 3 弦第 10 格；標準調音下第 2 弦第 6 格、第 1 弦第 1 格也是同一個音）。把「手指」推廣成 **(手指, 弦)** 這一對：手指 F 種、弦 S 種（各種吉他弦數不同）。難度函數照樣定義，只是同時看手指和弦。狀態變 F·S 種，轉換 (F·S)² 種，時間 **Θ(n·F²·S²)**。

### 推廣二：和弦，pose 有 (F+1)^F 種

現實中常同時彈好幾個音，叫 **和弦（chord）**；兩隻手的鋼琴更複雜。同一個和弦有好幾種指法，每個人喜好不同；和弦換和弦也有轉換難度，現在選哪種指法要看下一個和弦往哪移（例如先把小指空出來）。

- 輸入變成一串多音：notes[i] 是一組要同時彈的音。鋼琴一次最多 F 個音（一根手指只能按一個鍵）；吉他最多 S 個音（一條弦只能發一個音）。
- 現在要知道每一根手指在哪，手的整體擺法叫 **pose**。每根手指記「它按哪個音，或沒用到」，有 F+1 種選擇；F 根各自選，pose 共 **(F+1)^F** 種。對 F 是指數，不太好；但 F = 5 是 6⁵ = 7776 種，還可以。
- 子問題：從第 i 組音往後怎麼彈，已知第 i 組用某個 pose。猜：下一組音的整個 pose。
- 時間大約 n × (pose 數)²，就像原本的 F² 換成 pose 數的平方。F 小就還可以。

## Tetris

### 假設

同一套路，重點在子問題。先加幾個人為限制，讓 DP 處理得了：

1. 事先知道全部 n 塊的順序（比較像解謎）。
2. 每塊從頂端直接落到底；不准在最後一刻轉一下塞進縫裡。
3. 排滿的列不會消。這樣遲早會死，所以問題變成：**能不能撐過這 n 塊？**
4. 盤面寬度 w 很小（因為時間對 w 是指數；真正的 Tetris 寬 10）。
5. 盤面一開始是空的。

拿掉這些假設的一般 Tetris 是 NP-complete，計算上非常難；有了這些假設就能用 DP。

### 子問題：suffix + skyline

子問題先試 suffix：怎麼放第 i 塊以後的方塊。跟指法一樣，只有 suffix 不夠，還要知道現在盤面長怎樣。因為從頂端落下、又不消列，只在乎**每一欄疊多高**，每欄高度連起來叫 **skyline（天際線）**。盤面可能有洞，但方塊直直掉永遠到不了那裡，空間反正浪費了，把洞當成補滿就好。

- skyline 有幾種？每欄高度 0 到 h，h+1 種；w 欄各自獨立，共 (h+1)^w 種。
- 再乘上 n 種 suffix，子問題 **n·(h+1)^w** 個。對 h 還好，對 w 卻是指數，所以要假設 w 很小。

### 猜這一塊怎麼放

猜第 i 塊怎麼放：旋轉 0、1、2 或 3 次，再選從哪一欄落下，大約 4·w 種選擇。猜定之後算出新的 skyline，接到下一塊的子問題。時間 **O(n·w·(h+1)^w)**。

這題問的是「能不能活下來」，是第一個答案為 Boolean（true／false）的例子。把 true 當 1、false 當 0，就變成最大化，遞迴式取 max；base case 就是最後活下來了還是死了。

> **觀念** open problem：拿掉任一假設（w 很大、或會消列），還有好的 DP 嗎？目前不知道。

## Super Mario Bros.

### 離開畫面就重設

紅白機（NES）上的 Super Mario Bros. 1，這套想法適用很多橫向捲軸的平台遊戲。它有個好性質：**任何東西一離開畫面，就從世界消失**。關卡本身是靜態的，怪物上了畫面才開始動；畫面只能往右捲，怪物跑出畫面就不見了。所以離開畫面的那段等於重設回初始狀態，不用記。螢幕不太大這招才行得通，紅白機的螢幕剛好很小。

給整個關卡（大約 n bits）、螢幕 w×h 不大，就能用 DP。目標可以是分數最高，也可以是最快破關。

### Configuration 有幾種

這類 DP 先想清楚要記遊戲的哪些狀態，叫 **configuration**，要記的是螢幕上的一切：

- 怪物的位置。
- 物件的狀態：問號箱頂過沒、金幣拿了沒、香菇拿了沒。
- 每個小方格：磚塊？硬磚？被打掉的磚？有怪物？Mario 在這？每格常數 c 種可能，組合是 c^(w·h)。
- Mario 的速度：轉身比前進慢、會加速，但速度只有常數種。
- 目前分數（上限 S）與剩下的時間（上限 T，歸零就死）。S、T 是整數、可能很大，所以這是 **pseudo-polynomial** 的演算法。
- 螢幕在關卡的哪裡（往右走了多遠），取值數跟關卡長度有關。

configuration 總數就是全部相乘：對 w、h 是指數，再乘 S、T 和關卡長度。

### Configuration 圖上的 DP

有了 configuration，就知道往後怎麼玩需要的一切。時間計數器一直往下數，永遠不會回到同一個狀態，所以圖沒有環。

- 把所有 configuration 當點。每個點問：我能做什麼？按 A、放 A、按 B、放 B、按方向鍵，選擇常數種，出度是常數。按了某個鍵會到哪個 configuration，就連一條邊。
- 畫出整張圖跑最短路徑；或直接 DP：configuration 就是子問題（這題沒有 suffix），要最大化分數或剩餘時間就取 max。
- 每個子問題只連到常數個，總時間 = configuration 數 × 常數。螢幕、分數、時間都不太大，就能最佳化地破關。

> **觀念** 用遞迴加 memo 時，只會算從初始狀態走得到的 configuration，走不到的根本不碰。

## 跳舞機 DDR（Dance Dance Revolution）

結構很像吉他指法，但狀態少很多，比較好處理。

### 模型

第一件事：把遊戲變成模型，只留重要的。

- 踏板有四塊感應板：上、下、左、右，還有中間（腳可以站那裡休息）。
- 一張譜，畫面依序出現要踩的箭頭，每個叫一個 **note**，例如 ↑、↑↓、↓、↑↓、↑、↑↓、←→、←、←→、→ …
- 看到 ↑：某一隻腳一定要踩上，另一隻腳沒限制，放哪都行（例如一腳在上、一腳在中間）。沒有 note 時多踩幾下也不扣分。
- 踏板左右對稱，哪隻腳踩哪塊都沒差。

### 目標：機率相乘要取 log

這遊戲可以追求什麼？

1. 在自己的水準下分數最高（DP 處理的本來就是最大化或最小化）。
2. 很厲害、全部踩得到的話，追求最省力（比賽要連跳很多首，不想第一首就累垮）。
3. 動作好看，最大化娛樂效果（上台表演大概就贏在這）。
4. 比賽只跳一首，讓失敗機率最小（＝成功機率最大）。

整首成功的機率是每一步成功機率**相乘**（假設每步獨立），是乘積不是總和。取 log：log(a × b) = log a + log b，最大化乘積就變成最大化 Σ log pᵢ，跟平常的 DP 一樣了。

> **陷阱** 取 log 不只是理論方便。一堆接近 1 的數相乘會 **numerical instability（數值不穩定）**：例如兩種走法每步成功率 99.991% 和 99.992%，乘很多次之後浮點數讓乘積看起來都一樣，等於亂選一個。取 log 實務上也比較可靠。

### 力氣 δ 與 state、move

選一個目標來解：**全部踩到，總力氣最小**。其他目標都能化成這個：機率取 log，最大化就加負號。

定義 **δ(from, to)**：from 是跳之前兩腳的位置、to 是跳之後的，輸出 0 到 1（0 很輕鬆、1 很難）。例如 from：左腳 ↑、右腳在中間；to：左腳回中間、右腳 ↑。要跳一下，耗體力，δ 不是 0。每步都有難度，總和越小越好。

解法可以用 DP，也可以用圖；這裡用圖：

- 點代表 **state**：遊戲某個時間點的整體狀況。
- 跳一下是一個 **move**，從一個 state 連到另一個，也就是邊。

> **比喻** 像下棋：盤面加上輪到誰是 state，移動一顆棋是 move。

不管用圖還是 DP，最後都歸結到同一件事：**state 裡到底要放什麼**。

### 最佳走法併進 δ

一步的難度跟之前走過的步有關嗎？不會，這是好性質：每一步難度互相獨立（現實中會越跳越累，那是更進階的版本，這裡先假設你夠強、不會累）。

先找出解長什麼樣：一連串決策。譜上每個 note 都一定要產生一個 move，但 note 之間可能還有額外的 move。到底幾個？圖會不會大到跑不動？看例子：從 ↑↓ 換到 ←→，可以直接跳，也可以先到 ↑→ 再到 ←→。因為每步難度獨立，某條走法比較輕鬆，它每次都比較輕鬆，所以**乾脆把最好的走法直接算進 δ**。這樣兩個 note 之間永遠只要一個 move，圖不會爆炸。怎麼最好地換姿勢，正是學 DDR 時反覆練的基本步。

### 回到中間：需要一個中間 state

hold（長按）先當普通 note 處理。有一種情況真的需要中間步驟：譜是 ← → ← → ← →，有些人喜歡一有空檔就把腳收回中間。如果只能在 note 出現時動，兩腳卡在左右，每個 note 都得整個人跳，對膝蓋不好、對分數也不好。有了中間 state，就能踩完收回、再踩、再收回。

> **重點** 每兩個 note 之間加**一個**中間 state（多一個 move）就夠了：不用無限多中間步，回中間只要一步，初學者的動作都做得到。（高手其實是左右 rock：腳不太動，重心在兩腳之間換來換去。）

### 還要記重心

只踩一個箭頭時，如果重心在另一隻腳，輕輕點一下就好；但重心剛好壓在要動的那隻腳，就得整個人跳。差別在**重心（weight）**在哪隻腳。所以 state 要有 L、R、W：左腳位置、右腳位置、重心在左或右。

| 記什麼 | 種類數 |
|---|---|
| 兩腳位置（每腳 5 格：上、下、左、右、中） | 5 × 5 = 25 |
| 加上重心在左或右 | 25 × 2 = 50 |
| 再允許重心在正中間 | 25 × 3 = 75 |

重心放正中間時兩腳都難動，最佳打法不會這樣；但就算把它加進去，它不是最佳，DP 也會自動不選。（要是目標是娛樂效果，那種跳法搞不好比較帥。）

### State：(落在哪個 note, 兩腳在哪)

要分清兩個概念：**腳的位置**，以及**畫面上的 note**；腳必須符合 note。每次的決策是「怎麼跳」，也就是落地後兩腳的新位置；做決定時要知道落地那一刻畫面上是哪個 note。譜事先知道，記住它在清單中的 index，就知道之後畫面上的一切。

這很像 knapsack，但有個關鍵差別：knapsack 每個決策是選或不選（0/1），這裡的決策是新的腳位，所以 state 和遞迴式長得不一樣。例如現在要落在 note 2（←→），可能是從 note 1 的 ↑↓ 跳過來，也可能從 note 1 的 ←→ 過來；要比哪個來源好，就得知道之前的腳位。所以：

> **重點** state = (落在哪個 note 的 index, 落地後兩腳的位置)。這樣 δ(之前腳位, 現在腳位) 就算得出來。note 的 index 只會往前，時間只往前走，保證圖沒有環。

### 插入空白 note：改輸入，不改演算法

note 之間那一步額外的 move 怎麼放進模型？想沿用原本做法（拿落地腳位跟 note 比，看合不合規定），那就在每兩個 note 之間再插一個 note：發明一個**空白 note ○**，它沒有任何限制，腳愛放哪就放哪，它就是那個中間 state。把它插進輸入的每兩個 note 之間，圖上就多一層點。

> **觀念** 好處：改的是輸入，演算法不用改，建圖寫 DP 時只要處理 note 到 note 的轉移。能用這種「改輸入」的技巧就盡量用，它降低了複雜度。

目標：建一張圖，起點到終點的路徑長剛好是所有 δ 的總和，然後跑最短路徑。

### 建圖：點與邊

**點**：每個 note 搭配每一種它允許的腳位，都是一個點 (i, L, R)。一個 move 的難度只看從哪個腳位跳到哪個腳位，跟落點是不是空白 note 無關（就算錯過 note，花的力氣也一樣）。note 就是限制條件，規定哪些腳位可以：

| note | 允許的腳位 |
|---|---|
| 空白 ○ | 全收，25 種 |
| ←→ | 2 種：左腳左右腳右，或左右對調 |
| ↑↓ | 2 種：左上右下，或反過來 |
| 只有 ↑ | 一腳在上，另一腳在哪都行，不只 2 種 |

> **陷阱** 只有單一箭頭的 note，另一隻腳不受限，允許的腳位就不只 2 種。算權重時要知道確切的落地腳位，因為一個 note 可能允許好幾種。

例如 note 4 是 ↑↓，只有 2 個點，前一層每個點都連到這 2 點。整張圖起點出度很大、中間一大片，像一個亂掉的 sorting network。

**邊**：從點 (i, L, R) 連到第 i+1 個 note 的每一個允許的落點 (i+1, Lⱼ, Rⱼ)，權重 δ((L, R), (Lⱼ, Rⱼ))。目標是最小化難度，這樣就對了；要最大化（例如分數、好看程度），就把權重加負號：最大化 x 等於最小化 −x，再跑最短路徑。

**起點與終點**：一開始腳要站哪？加一個 note 0，放所有可能的腳位，讓我們自己選起始站姿；source 用權重 0 的邊連到 note 0 的每個點（站姿自己挑、不花力氣；有的站姿會讓第一步比較難，就讓最短路徑幫我們挑）。終點：最後一個 note 的每個點用權重 0 的邊連到 t；或不加 t，把它們都當終點、挑最近的，效果一樣。

### 用哪個最短路徑演算法

δ 都在 0 到 1，沒有負的，Dijkstra 可以用；也可以用 Bellman-Ford。但最好的答案是都不用：這是 DAG，照拓撲順序每條邊 relax 一次就好（DAG shortest path，O(V + E)），更快。

> **陷阱** 「做 DP 就是跑 DAG 最短路徑」大多數時候對，但不是全部：矩陣連乘（加括號）要把兩個子問題相加，就不是最短路徑。

## 重點整理

- DP 五步驟：定義子問題（數個數）→ 猜（多項式種）→ 遞迴式（min/max）→ memo 或 bottom-up（acyclic ⇔ 有拓撲順序）→ 解原問題。時間 = 子問題數 × 每個子問題時間。
- 序列的子問題：suffix x[i:]、prefix x[:i] 各約 n 個；substring x[i:j] 約 n² 個。同時需要 prefix 和 suffix 時改用 substring。
- 兩矩陣 p×q 乘 q×r：p·q·r 次乘法，結果 p×r。A×B 能乘不代表 B×A 能乘；矩陣乘法有結合律、沒有交換律。
- 矩陣連乘：m(i,i) = 0；m(i,j) = min over i ≤ k < j { m(i,k) + m(k+1,j) + d(i−1)·d(k)·d(j) }；依 j−i 由小到大填；s(i,j) 記最佳 k，用來還原括號（in-order 印括號）。
- 0 編號版：DP(i,j) = min over i < k < j { DP(i,k) + DP(k,j) + 合併成本 }，base DP(i,i+1) = 0，答案 DP(0,n)。
- 括法數 = Catalan 數 (2n 取 n)/(n+1)，n = 矩陣數 − 1：4 個 5 種、5 個 14 種，約 4ⁿ 級。
- 矩陣連乘 Θ(n³)（約 n² 格 × 每格 n 個 k）；它不是 DAG 最短路徑。
- 例題：維度 5,4,6,2,7 → m = 120, 48, 84 / 88, 104 / 158，括法 ((A₁(A₂A₃))A₄)；維度 3,2,4,2,5 → 24, 16, 40 / 28, 36 / 58，括法 (A₁(A₂A₃))A₄。
- BST：n 個 key 有 (2n 取 n)/(n+1) 棵、n+1 個 external node；成本 = Σ 層數 × 頻率；最好的樹不一定最矮（例：頻率 3,2,5 最佳 17，平衡樹 18）。
- Optimal BST：c(i,j) = min over i < k ≤ j { c(i,k−1) + c(k,j) } + w(i,j)；r(i,j) 記 root；左子樹 (i,k−1)、右子樹 (k,j)；表的 i 從 0 開始。
- 成功＋失敗：w(i,i) = qᵢ，w(i,j) = w(i,j−1) + pⱼ + qⱼ；期望成本 = Σ pᵢ·level + Σ qᵢ·(level − 1)（Horowitz；CLRS 方塊算 level）。
- 例題：頻率 4,2,6,3 → 26，root 30；p = 3,3,1,1、q = 2,3,1,1,1（×16）→ 32/16 = 2，root 20。
- Reliability：stage 可靠度 1 − (1 − r)^m；上限 uᵢ = ⌊(C − Σcⱼ)/cᵢ⌋ + 1；集合法 (reliability, cost) 從 (1, 0) 開始；先刪錢不夠的，再用 dominance rule 刪又貴又不可靠的；例題答案 D₁×1、D₂×2、D₃×2，0.648、100 元。
- Edit distance：DP(i,j) = min(取代 + DP(i+1,j+1), 插入 yⱼ + DP(i,j+1), 刪除 xᵢ + DP(i+1,j))；i、j 都倒著算；Θ(|x|·|y|)，空間可降到線性。
- LCS = edit distance 的特例：插入、刪除 1，相同字母取代 0、不同字母 ∞。HIEROGLYPHOLOGY／MICHELANGELO → HELLO。
- Knapsack：DP(i,X) = max(DP(i+1,X), DP(i+1,X−sᵢ) + vᵢ)，「放」的選項需 sᵢ ≤ X；O(n·S) 是 pseudo-polynomial（輸入只有 n·log S 個 bit）。
- 第二種猜：子問題多加參數記住過去（knapsack 的剩餘容量、指法的手指、Tetris 的 skyline、Mario 的 configuration、DDR 的腳位）。
- 指法：DP(i,f) = min over g (d(note[i], f, note[i+1], g) + DP(i+1,g))，答案 min over f DP(0,f)，Θ(n·F²)；吉他 Θ(n·F²·S²)；和弦 pose (F+1)^F 種。
- Tetris：子問題 n·(h+1)^w，每個猜 4·w 種，O(n·w·(h+1)^w)；答案是 Boolean，當 0/1 取 max。
- Mario：configuration（螢幕內容、速度、分數 S、時間 T、捲軸位置）是子問題，pseudo-polynomial，時間 = configuration 數。
- DDR：機率相乘取 log；最佳中途走法併進 δ；每兩個 note 之間插空白 note ○；state = (note index, 兩腳位置)，重心 25 → 50 → 75；source 用 0 權重邊接 note 0；DAG shortest path。
