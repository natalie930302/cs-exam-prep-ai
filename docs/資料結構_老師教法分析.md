# 資料結構：四位老師的教法分析（完整版）

依據：網站上資料結構 80 支影片（約 86 小時）的逐字稿，**每一支都從頭讀到尾**。
限制：只看得到老師「說出來的話」；黑板、投影片上沒念出來的圖和算式看不到。凡是要看圖才能判斷的地方，下面都不下結論。

## 二、相同的地方

1. **考試核心主題，至少兩家都有教**：陣列、linked list、stack/queue、樹的走訪、BST、AVL、heap、hash、BFS/DFS、MST、最短路徑、排序。講出來的演算法步驟本身大致一致。
2. **都靠一個具體例子跑一遍**。差別只在跑得多細（Bari、彭最細）和跑之前有沒有先講為什麼（林、MIT 會）。
3. **都很少講完整的時間複雜度推導**。只有 MIT（build heap、AVL 高度、排序下界、radix）和林（攤銷、Big-O 證明）有真的推導；Bari 和彭多半一句話帶過，而且這一句常常有錯。
4. **都會有字幕看不到的板書**，尤其 Bari 的圖、彭的投影片。

## 三、不同的地方

### 1. 切入方式完全不同
- **Bari**：不講動機，直接「我們來做」，一格一格畫。好處是零門檻；壞處是不知道為什麼要這樣做。
- **林軒田**：一直問「為什麼要這樣設計」。例如 heap：先說「最大的放 root」，一路修正到 Binary Max Tree，再加 complete 才得到 Max Heap。紅黑樹是從 2-3-4 樹推出來的。這是全站理解「為什麼」最好的老師。
- **彭文志**：照 Horowitz 投影片和程式一行一行講，邊講邊提示「期中考會出這個」。最像考試。
- **MIT**：先說明為什麼別的資料結構不夠好（例如 BST 那講用 20 分鐘排除 list、array、heap），再證明。

### 2. 比喻
- 林：記憶體＝最大的 array、指標＝小紙條、AVL 旋轉＝孫子篡位、2-3-4 樹＝房子和房間、快車慢車（skip list）。
- 彭：可麗餅排隊（queue）、資源回收（free pool）、看圖說故事（指標）、擋修（AOV）、搓湯圓。
- Bari、MIT：比喻很少，靠圖和例子。

### 3. 定義和用詞不一致（考試最容易錯）
| 項目 | 台灣課本（Horowitz）＝彭 | 林軒田 | MIT | Bari／短片 |
|---|---|---|---|---|
| 樹的 level／高度 | root 在 level **1** | root 在 depth **0**，公式差 1 | 高度用邊數算，葉子 0、空樹 −1 | AVL 那支前後不一；BST 短片從 0 |
| complete／full | complete＝最後一層靠左 | 同課本 | MIT 的 complete＝課本的 **full**，nearly complete＝課本的 **complete** | — |
| 旋轉名稱 | LL、LR、RR、RL | RR、RL 通式 | right rotate／left rotate（LL 型＝right rotate） | LL、LR、RR、RL |
| external node | extended binary tree 的虛擬節點 | 指葉子 | — | — |
| dictionary | key 不重複 | 一個 key 對多個 value（剛好相反） | — | — |
| 2-3-4 樹插入 | top-down split | **bottom-up** split，中間過程不同 | — | — |
| binomial heap | lazy、min | eager、max | — | — |
| B-tree 的 order | — | — | — | Bari：最多子節點數；彭（B+ tree）：最少 key 數 |
| KMP 失敗函數 | 0-based、沒有就 −1 | — | — | 1-based π（差 1） |

> 結論：**考試用詞一律以彭文志（＝課本）為準**；看其他老師時，要把他們的定義換算回來。

## 五、哪個教得比較好？

沒有一位全面最好，因為他們做的是不同的事：

- **最好上手：Bari。** 圖多、步驟慢、一步不漏，第一次學幾乎不會卡。但只學他會「會做不知道為什麼」，而且他講的複雜度常錯。
- **最懂「為什麼」：林軒田。** 紅黑樹、heap 的設計動機、排序性質、binomial heap 是全站最好的來源。但約 3 成時間是課務閒聊、幾乎不做考試格式的手算、幾個定義和課本不同，**不能當考試唯一來源**。
- **最像考試：彭文志。** 考試答題拿最高評價的主題最多，很多考點只有他教（optimal BST、external sort、AOE、Floyd、關節點、fast transpose）。**但他是錯誤最多會直接影響答題的老師**（見下一節），看的時候一定要對照錯誤表。
- **證明最強：MIT。** AVL 高度、build heap O(n)、排序下界只有 MIT 有。但手算例子少、用詞和台灣課本相反。

**組合起來最有效的順序**：Bari 學會怎麼做 → 林軒田懂為什麼 → 彭文志練考試格式和課本名詞 → MIT 補證明。每個主題不必每家都看，照上表挑。

## 六、會直接影響考試的錯誤（看影片時要知道）

### 彭文志
- 演算法的條件包含「有效率」（錯，Knuth 五特性沒有這條）。
- 「QuickSort 是最快的，連最壞情況都是」（錯，最壞是 Θ(n²)）。
- indirect recursion 的定義講錯（Lec01、Lec02 兩次都一樣）。
- 迷宮最短路徑的提示用 stack/DFS（錯，最短路徑要 BFS）。
- 「array 刪除比 linked list 快」（錯）。
- KMP 失敗函數念課本的定義，卻算 CLRS 的值（兩種慣例混用）。
- max heap 說成「root 最大、下面不管」；「heap[2] 就是第二大」（錯，要比 index 2 和 3）。
- **collapsing rule 講錯**（課本是每次 find 都壓縮）。
- **「MST 的貪婪法不保證最佳」**（錯，總成本一定最小）。
- **「DFS 樹的 root 一定是關節點」**（錯，要兩個以上子節點）。
- **「B-tree 的資料都存在 leaf」**（那是 B+ tree）。
- mid-square 順序講反；division 說看「最左邊」的 bit。

### Abdul Bari
- BFS/DFS 是 O(n)（應為 O(n+e) 或 O(n²)）。
- Kruskal 時間、union-find「常數時間」、hashing「比 log n 快」都講錯或太粗。
- 生成樹個數公式錯（連他自己的例子都不成立）。
- 「二維陣列要用雙重指標」（錯）。
- Heap sort 用反覆插入建 heap，跟課本 bottom-up 的手算結果不同。
- Rabin-Karp 建議 mod 2³¹／2³²（應用質數）。

### 林軒田
- 「2ⁿ、5ⁿ 的底可以吸收進常數」（錯；他後來承認講得太隨便，但沒講正確結論）。
- ordered array insertion 那段程式**故意留了 bug**，不能照抄。
- AVL 刪除補位說法不精確；紅黑樹 double black 的例子他自己說可能有錯。
- hash 的除法沒提要選質數。

### MIT
- L6 把 left rotate 說成 right rotate（44:55）。
- 「AVL 插入修完上面可能還要修」（只有刪除才會）。
- Rec6 說 AVL 高度常數「2 到 3」（應為約 1.44）；「同一層兩個節點高度最多差 1」（錯，只限兄弟）。

## 七、這份分析跟第一版比較有什麼不同

第一版有一部分是看分段重點推的，這次全部讀完後更正了不少，例如：
- 林軒田的 Analysis Tools 其實是**補錄**的，時間上在 linked list 之後，開頭就預設你學過 binary search 和 linked list。
- 林軒田的 traversal 其實在 Tree/Heap 那支（10:26–40:43），不是「在別支影片」。
- 彭文志 collapsing rule 第一版當成講對，其實講錯。
- 彭文志 optimal BST 的 c04 第一版寫 16，正確是 32（16 是 w04）。
- MIT Rec9b 被放在字串比對，但它其實沒教任何字串比對演算法。
- -b2lciNd2L4（印地語走訪）的中文翻譯其實可以看，不必跳過。
- 4tSdhWBVv6A 的逐字稿只涵蓋約 34% 的時間，網站上很難跟。
