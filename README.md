# 資工所備考中心 — 打包說明

## 修正內嵌 Codex `parse_failed`（2026/8/25）

AI橋接程序現在會明確傳入Windows的`HOME`、`USERPROFILE`與`CODEX_HOME`，並要求網站服務以可讀寫
Codex登入狀態的正常本機權限啟動。無JSON事件時不再籠統顯示`parse_failed`，而會回傳CLI最後一行
可理解的錯誤。以「作業系統／虛擬記憶體」5題診斷實際測試，已成功產生並保存第1題。

## 全站自適應學習系統（2026/8/25）

新增學習計時、診斷作答、錯誤類型、間隔複習、素材偏好、前置知識、學校別準備度與每週檢討資料層。
日曆首頁新增四張智慧摘要：依個人速度校準的今日安排、到期複習、必考弱點，以及近期正確率／目標校
準備度。六科各章可直接開始AI診斷、回報分數、回報複習品質與記錄實際時間；影片系列可評1–5分，
往後同章多位老師會優先排列較適合使用者的來源。

AI工具新增`get-smart-dashboard`、`record-review-result`、`log-study-time`與`rate-material`，並讓
`record-practice-result`同步建立作答紀錄與下一次複習日期。所有新證據皆納入進度備份／還原。影片
內容審查沿用章節考點、單集標題、HackMD與練習的證據包；公開字幕可取得時才建立字幕索引，沒有字幕
或YouTube限流時明確降級為標題推定，不虛構逐字內容。

## 基礎期加入一週補課緩衝（2026/8/25）

基礎內容仍以11/21完成為目標，但11/22–11/28改為恢復／補課週，預警基準延至11/29。以每天5小時
計算，307小時任務對應350小時容量，留下約43小時（約14%）緩衝，足以吸收臨時少讀數天、影片重看
與難題卡關。任務若提早完成會立即進入刷題期，不必空等；若落後則自動使用緩衝週順延。素材頁不再把
11/22寫成硬性刷題起點，避免與佇列驅動的真實進度矛盾。

## 基礎期估時與行程容量校正（2026/8/25）

影片任務不再一律估1小時，改為加總該週指定單片的真實時長；同主題替代老師仍只計選定的一套，不會
重複灌入時數。週曆每天顯示2＋2＋1小時，因此進度預測容量由6小時校正為5小時。完工預測另保留10%
機動緩衝：工作量超過容量時顯示確實缺口，能完成但緩衝不足時則顯示剩餘機動時數。瀏覽器與AI工具
共用同一套影片時長算法，避免頁面與AI回報不一致。

## AI 新增章節教材覆蓋審查（2026/8/25）

`tools/plan-tool.js`新增`audit-learning-coverage`：AI可把單章核心考點，與依序排列的單片影片、
紙本範圍、練習要求、同科HackMD來源及已核實的筆記提醒一起比較。回覆必須區分充分覆蓋、僅由
標題推定、缺少做題驗證與明顯缺口；影片沒有逐字稿時不得假稱已完整看過內容。這讓AI能用素材與
真實進度提出補強建議，而不是用影片數量判斷「夠不夠」。

## AI 掌握程度改為「完成紀錄＋作答證據」雙層推估（2026/8/25）

章節打勾不再直接等同於真正掌握。系統會依影片、紙本、練習與筆記的完成狀態先建立低信心估計；
使用者回報小測驗或考古題的正確題數後，再以教材完成度35%與作答表現65%計算章節掌握程度，並依
必考程度與預估時數找出各科最需要補強的章節。AI 可查詢每章的推估分數、信心、狀態與下一步，
但只有在使用者明確提供正確題數與總題數時才能寫入作答證據，不得自行臆測。

作答證據存於SQLite的`mastery_evidence`資料表，並納入既有進度匯出／匯入備份；舊版備份沒有此欄位時
仍可正常匯入。

## AI 可查詢完整教材與章節進度（2026/8/25）

AI 助教不再只取得基礎期總任務數與剩餘工時。`tools/plan-tool.js`新增四個唯讀查詢：全局學習情境、
單科教材總覽、單章完整教材，以及跨科素材搜尋。查詢結果會區分完整 YouTube Playlist 與章節指定單片，
提供紙本書名／講義、對應閱讀範圍、影片老師／OCW系列、系列內順序、單片時長與連結、練習內容，以及
video／book／practice／notes各類任務的真實完成狀態。`AGENTS.md`同步要求 AI 在回答教材、下一步與
進度相關問題前先查詢，不得猜測標題、連結、時長或完成狀態。

## 章節教材新增「多版本影片合併」UI，同主題多位老師只需完成任一支（2026/8/23）

延續上一輪的revert，使用者進一步指定機制：同一章節裡，若同一個narrow主題有多位老師/OCW版本，
不該只是「刪掉多的、留一支」，而是要合併成一個任務列，底下並排多個可點擊的影片連結，看完任一個
就算完成整列——而不是繼續個別列成好幾支獨立任務。

- `data.js`新增`mats`項目型別`vidgroup`：`{type:"vidgroup", text, options:[{label,url,dur}, ...]}`。
- `app.js`的章節教材渲染（`chaptersHtml`裡的`matsHtml`）新增對應分支：整組只用一個checkbox
  （一個`mat-*`任務id），點連結只開影片不勾選（`stopPropagation`），點列本身才切換完成/未完成。
  同時修掉一個既有的小bug：舊版渲染程式碼裡的`'<\a>'`、`'<\span>'`（單引號字串裡的`\a`/`\s`是
  JS不認得的跳脫序列，會被靜默丟掉反斜線，執行時變成錯誤的「重複開標籤」而非該有的收合標籤）。
- `styles.css`新增`.ch-mat-group`／`.mat-opt`等樣式，讓每個影片版本顯示成小圓角按鈕，並排在同一列。
- 分組原則：只合併「同一個narrow主題的不同來源/不同老師講法」（含單一老師的連續多集系列視為一條
  path），像是不同的Backtracking例題、不同DP應用、KMP vs Rabin-Karp這種**內容本身不同**的影片
  不合併，維持各自獨立任務。
- 已套用到資料結構（DS）、演算法（ALG）、作業系統（OS）、線性代數（LA）全部章節，共61組
  vidgroup，並以腳本驗證每組`options`都有合法的`label`/`url`。離散數學（DM）、計算機組織（CA）
  的章節教材主要是「兩位老師各自的完整連續課程系列」（不是單支影片的narrow主題替代關係），沒有
  適合合併的pair，維持原樣（`tip`欄位已提醒不用兩套都看）。

## 週曆／月曆未來日期改成「順延投影」而非永遠卡在同一週（2026/8/22）

使用者問：「勢力（進度）月曆的task任務安排要幫我順延全部排完啊？先預設一版本的，如果隔夜了還沒弄完
在幫我順延排到隔天之類的」。

背景：基礎期的`dayInfo(d)`本來不管傳進去的日期`d`是哪一天，週次永遠回傳「當下佇列」的`effectiveWeek`
（佇列制，不是行事曆制——這是刻意設計，落後不會被新內容悄悄蓋過去）。副作用是週曆往後翻、月曆往後看，
每個未來日期顯示的都是同一個「卡住的」週次內容，沒有真的往後推。

- **新增`projectedWeekForDate(d)`**（app.js，`foundationForecast`後面）：對於今天之後的日期，不是照抄
  `effectiveWeek`，而是從「今天」開始模擬——用跟`foundationForecast()`一樣的每週節奏假設
  （`DAILY_CAPACITY_HOURS`：日休、一打工不排、二～六各6hr），把目前真實剩餘的分鐘數（依週分組、只算
  未完成的任務）依序往後排，算到第`d`天時「餘額」花到哪一週還沒花完，就回傳那一週。這是**純推算**，
  不是儲存一份新行事曆——沒進度就不會前進，進度快就會自動往前拉，不需要額外的資料表或手動「順延」動作。
- **`buildWeekDayBlocks(d, info)`**：基礎期分支裡，`d`若晚於今天，改用`projectedWeekForDate(d)`決定要
  顯示哪一週的科目／章節卡片（含點擊跳轉六科的`wk`），今天以前（含今天）維持原本的`info.wk`不變。
- **`buildCalMonthCells()`**：月曆的科目標籤同步套用同一個投影函式，未來日期不再顯示卡住的週次。
- 效果：沒做完的任務不會消失，只是往後的日期會反映「照現在剩下多少量、正常節奏推算，實際上大概哪一天
  會讀到哪裡」——真的落後，未來幾天的卡片會自動往後移；今天補進度追上了，投影也會自動跟著往前拉。

- 已用 Playwright 驗證：（1）既有的完整迴歸測試（5分頁、週/月曆切換、章節checkbox、AI助教等）全數通過；
  （2）針對投影邏輯的新測試——用純記憶體覆寫`DONE_TASK_IDS`模擬「已完成第1週」但不寫回真實資料庫，確認
  1天後的日期仍顯示目前的`effectiveWeek`（還沒差到需要往後推），30天後的日期則正確投影到更後面的週次。

## AI 助教怎麼運作

側邊欄「AI 助教」分頁是一個聊天框。你送出訊息後，`server.js` 會在背景執行一次
`claude -p`（跟你現在用的這個 CLI 是同一套），把你的訊息用 stdin 餵進去，
拿到的回覆顯示在網頁上。同一個對話串會用 `--resume` 接續上下文，直到你按「開始新對話」。

它能做兩件事：
1. **純問答**——直接用它自己的知識回答，不會動到任何資料。
2. **查詢/調整進度**——問它「我讀到哪了、還剩多少小時」，它會執行
   `node tools/plan-tool.js get-queue-status` 給你真實數字（不是用猜的）。如果你說某個任務做完了、
   或想跳過某個任務，它可以用 `mark-done <task-id>` / `mark-undone <task-id>` 幫你打勾。

花費。

如果 `claude` CLI 不在 PATH 上，或還沒登入，聊天會回傳錯誤訊息，其他功能（今日任務、checklist等）
不受影響。

- 階段判斷是動態計算的（`app.js` 的 `dayInfo()`）：`CONVERGENCE_DAYS` 是相對考試日期算的硬性
  截止線（不管進度如何，離考試21天內一定進收斂期）；基礎期用 `getFoundationQueueStatus()` 算
  ——顯示第幾週＝「第一個還沒打勾的任務所在那一週」，基礎期65項任務都做完才會進刷題期
- 任務佇列：`buildFoundationTasks()`（app.js）把 `FOUNDATION_CONTENT`/`FOUNDATION_TASK_TEXT` 攤平成
  65 個原子任務；`tools/plan-tool.js` 有一份輕量的平行目錄（只有 id+分鐘數，沒有標題/連結）算彙總數字
  給 AI 用——如果改了 app.js 的 `FOUNDATION_BOOK_MINUTES`，記得同步改 plan-tool.js 那份
- API：`GET/POST /api/settings`、`GET /api/tasks/done`、`POST /api/tasks/:id/toggle`、
  `GET /api/checklist/:date`、`POST /api/checklist/:date/toggle`、
  `POST /api/chat`、`GET /api/chat/history`、`POST /api/chat/reset`
- AI 橋樑注意事項（Windows）：`--allowedTools "Bash(node tools/plan-tool.js:*)"` 這種帶括號的值
  透過 Node `child_process.spawn(..., {shell:true})` 傳遞時，Windows 的 shell 引號處理會把它弄壞、
  導致工具權限被靜默拒絕；改用 `--settings tools/agent-settings.json`（純路徑，無特殊字元）就沒事。
  系統提示同理改放 `CLAUDE.md`（`claude` CLI 會自動從 cwd 讀取），不透過 argv 傳遞長字串。
